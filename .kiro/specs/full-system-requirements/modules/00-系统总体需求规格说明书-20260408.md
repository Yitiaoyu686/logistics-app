## 1. 系统定位

跨境物流全链路管理平台（TMS/ERP），面向中国→非洲（尼日利亚/加纳）方向的海运/空运货代公司内部运营团队。

**当前定位**: 产品经理需求Demo原型，后端Express+SQLite已连通，前端通过axios调用REST API。

---

## 2. 系统架构

### 2.1 技术栈

| 层级 | 技术 | 说明 |
|------|------|------|
| Web前端 | React 19 + TypeScript + Ant Design v6 + Vite 7 | SPA，无React Router，state-driven导航 |
| 移动端 | React 19 + Ant Design Mobile v5 + React Router v7 | 独立H5应用 |
| 后端 | Express 5 + TypeScript + better-sqlite3 | REST API，JWT认证 |
| 数据库 | SQLite (better-sqlite3) | 轻量级关系型 |

### 2.2 导航架构

```
顶部域切换: 综合协同(ALL) / 海运业务(SEA) / 空运业务(AIR) / 系统管理(SYS)
   ↓
左侧菜单: 根据 域(domain) × 角色(role) 双维度过滤
   ↓
卡片式Tab: 模块内子页面切换
   ↓
面包屑: 首页 > 域名 > 模块名
```

### 2.3 认证体系

- JWT Token 认证，localStorage 持久化(token + user JSON)
- ngrok环境自动清除本地存储
- 登录成功后根据角色确定默认域和菜单

## 4. 核心业务实体关系

```
Client (客户)
  └── MasterOrder (主订单) 1:N
        ├── SubOrder (子订单) 1:N
        │     └── ShippingUnit (集装箱/托板) N:1
        │           └── Job (运输任务) N:1
        ├── ExpressPackage (快递包裹) 1:N
        └── Fee (费用) 1:N

Job (任务)
  ├── NodeUpdate (节点更新) 1:N
  ├── JobCost (任务成本) 1:N
  └── DPN (派送单) N:M
        ├── DeliveryTask (配送任务) 1:1
        └── PickupRecord (自提记录) 1:1

Transfer (调拨单) — 仓间调拨
Return (退运单) — 退运处理
PettyCash (备用金) — 财务备用金
CashFlow (收支流水) — 资金管理
SalaryRecord (薪资记录) — 薪资发放
```

## 5. 核心状态机

### 5.1 主订单状态

```
PENDING_INBOUND → INBOUND → PENDING_DEPARTURE → DEPARTED → IN_TRANSIT → ARRIVED → PARTIAL_DELIVERED → COMPLETED
                                                                                                        ↗
任意早期状态 → CANCELLED (取消)
任意非终态 → RETURN_APPLIED → CANCELLED(通过) / 恢复原状态(驳回)
任意非终态 → SUSPENDED (暂停) → 恢复原状态
```

### 5.2 子订单状态

```
PENDING_INBOUND → INBOUND → PENDING_PACKING → PACKED → PENDING_DEPARTURE → IN_TRANSIT → CUSTOMS_CLEARANCE → ARRIVED → PENDING_DELIVERY → DELIVERING → DELIVERED
```

### 5.3 任务状态

```
PENDING → IN_PROGRESS → COMPLETED
任意非终态 → SUSPENDED → 恢复为IN_PROGRESS
```

### 5.4 退运状态

```
PENDING_APPROVAL → APPROVED → SETTLING/SETTLED → EXECUTING → COMPLETED
PENDING_APPROVAL → REJECTED
任意状态 → CLOSED
```

### 5.5 DPN状态

```
DRAFT → PENDING_ASSIGN → ASSIGNED → IN_TRANSIT → DELIVERED → SIGNED
任意状态 → CANCELLED
```

### 5.6 费用审核状态

```
DRAFT → PENDING → APPROVED / REJECTED
APPROVED → (申请修改) → 生成CHANGE行 → PENDING → APPROVED/REJECTED
```

### 5.7 备用金状态

```
PENDING → APPROVED → PAID → VERIFIED
PENDING → REJECTED
```

## 9. 全局交互规范

### 9.1 列表页标准模式
1. 统计卡片区（顶部彩色数字）
2. 搜索/筛选工具栏（左搜索+右主操作按钮）
3. 数据表格（Ant Design Table，支持排序/分页/展开行）
4. 操作列（蓝色文字链接）

### 9.2 详情页标准模式
- Drawer抽屉（左侧Anchor锚点导航 + 右侧Card区域滚动）
- 或 Modal弹窗（表单编辑）

### 9.3 表单标准模式
- Drawer/Modal + Form，labelCol=6/wrapperCol=18
- 必填字段红色星号，校验失败红色提示
- 提交按钮在右上角(Drawer.extra)或底部(Modal.footer)

### 9.4 状态标签色彩体系
- 蓝色: 信息/进行中
- 绿色: 成功/完成
- 橙色: 警告/待处理
- 红色: 错误/异常/紧急
- 紫色: 特殊(如API权限类型)
- 默认灰: 已关闭/已取消

### 9.5 费用显示规范
- 按币种分组展示（$USD / ¥CNY / ₦NGN）
- 每组显示小计
- 金额精度2位小数
- 收入/应收绿色，支出/应付红色
