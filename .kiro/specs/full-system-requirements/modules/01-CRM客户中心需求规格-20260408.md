## 1. 状态枚举定义

### 1.1 ClientStatus（客户状态）

| 枚举值 | 中文名称 | 说明 |
|--------|---------|------|
| `ACTIVE` | 活跃 | 正常跟进中的客户 |
| `DORMANT` | 沉睡 | 长期未有订单的客户 |
| `FROZEN` | 冻结 | 被冻结的客户，不可操作 |

### 1.2 ClientPoolType（客户池类型）

| 枚举值 | 中文名称 | 说明 |
|--------|---------|------|
| `PRIVATE` | 私海 | 归属于特定业务员的客户 |
| `PUBLIC` | 公海 | 未分配或被释放的客户 |

### 1.3 WarehouseEntryStatus（入仓号状态）

| 枚举值 | 中文名称 | 说明 |
|--------|---------|------|
| 待使用 | 待使用 | 生成后尚未关联订单 |
| 已关联 | 已关联 | 已关联到某个订单 |
| 已入库 | 已入库 | 货物已实际入库 |
| 已失效 | 已失效 | 被作废的入仓号 |

**状态流转规则：**
- 待使用 → 已关联（关联订单时）
- 已关联 → 已入库（实际入库时）
- 待使用 → 已失效（作废操作）

### 1.4 ClientPoolLog.action（公海日志操作类型）

| 枚举值 | 中文名称 | 说明 |
|--------|---------|------|
| `CLAIM` | 认领 | 从公海认领客户到私海 |
| `RELEASE` | 释放 | 业务员主动释放到公海 |
| `TRANSFER` | 转移 | 在业务员之间转移客户 |
| `AUTO_RELEASE` | 自动回收 | 系统自动回收至公海 |

### 1.5 ClaimRequest.status（认领审核状态）

| 枚举值 | 中文名称 | 说明 |
|--------|---------|------|
| `PENDING` | 待审核 | 已提交认领申请，等待审核 |
| `APPROVED` | 已通过 | 审核通过，客户已划入私海 |
| `REJECTED` | 已驳回 | 审核未通过 |

### 1.6 信用等级（CreditLevel）

| 等级 | 中文名称 | 颜色标签 |
|------|---------|---------|
| A | A级优秀 | `green` |
| B | B级良好 | `blue` |
| C | C级一般 | `orange` |
| D | D级较差 | `red` |

## 4. 我的客户列表

> **业务描述**
>
> **背景与目的：** 销售人员管理自己名下的客户，是创建订单的前提。每个客户拥有唯一的4位客户编号（shortCode），用于全系统标识。
>
> **使用角色与场景：** 销售人员（SALES）为主要使用者，起运国操作（OPS_CN）和管理员（ADMIN）也可查看和管理。销售通过线上推广、老客介绍、展会等渠道获取客户信息，录入系统后成为"私海"客户归属该销售。
>
> **前置条件与触发时机：** 用户登录系统后进入 CRM 模块，默认展示当前登录销售名下的私海客户列表（poolType = PRIVATE）。
>
> **数据来源与去向：** 数据来源为手动录入或从公海池认领转入。数据去向方面：客户数据被 OMS 订单中心引用（创建订单时选择客户→自动带出发货人/收货人/入仓号）；被财务模块引用（应收管理按客户维度汇总）。
>
> **入仓号机制：** 每个客户可生成多个入仓号（格式：`{客户编号}{3位流水}`，如 `284Y003`），入仓号用于客户将快递寄到仓库时标识货物归属。入仓号状态流转：待使用→已关联（订单引用）→已入库（货物到仓）→已失效（手动作废）。
>
> **与其他模块的联动：** OMS 订单中心创建订单时引用客户和入仓号；WMS 仓储根据入仓号识别到货归属；财务模块按客户维度汇总应收。
>
> **边界规则：** 同一客户不可重复创建（按名称+联系电话去重）；删除客户前需确认无关联订单；转移跟进仅变更 salesId，不影响历史订单归属。

## 5. 公海池

> **业务描述**
>
> **背景与目的：** 公海池存放无人跟进的客户线索，任何销售均可申请认领。目的是防止客户资源浪费，促进销售之间的良性竞争，提高客户转化率。
>
> **使用角色与场景：** 销售（SALES）浏览公海客户并申请认领；管理员（ADMIN）、起运国操作（OPS_CN）、管理层（BOSS）负责审核认领申请。典型场景包括：1）销售手动录入线索到公海；2）长期无订单的私海客户被系统自动回收到公海；3）销售主动释放客户到公海。
>
> **前置条件与触发时机：** 用户进入 CRM 模块切换到"公海池"Tab 即可查看。认领操作需点击"申请认领"按钮发起流程。
>
> **认领流程：** 销售申请→进入公示期（其他销售可查看该申请）→审核人审批（通过/驳回）→通过后客户转入申请人的私海（salesId 更新为认领人）。
>
> **数据来源与去向：** 来源包括：私海释放、系统自动回收（长期无订单）、手动录入线索（poolType 直接设为 PUBLIC）。去向：认领通过后客户转入私海，salesId 更新为认领人 ID。
>
> **与其他模块的联动：** 公海客户被认领转入私海后，即可在 OMS 中为该客户创建订单。公海流转记录（认领/释放/回收）写入 ClientPoolLog，在客户详情"跟进记录"Tab 中展示。
>
> **边界规则：** 同一客户只能有一个待审核的认领申请（PENDING 状态唯一）；审核期间客户不可被其他人申请；驳回后可重新申请。

- `ADMIN`（管理员）

### 5.4 申请认领流程

1. 业务员点击"申请认领"
2. 系统创建 ClaimRequest，状态为 `PENDING`
3. 具有审核权限的角色在"认领公示审核表"中审核
4. 审核通过：客户 poolType 由 PUBLIC → PRIVATE，分配 salesId
5. 审核驳回：记录驳回原因，客户保持在公海

## 6. 客户详情

> **业务描述**
>
> **背景与目的：** 客户详情是客户的完整档案页面，包含基础信息、企业资质、物流地址簿、关联订单、交易统计、公海流转记录、入仓号管理共7个维度的信息，供业务人员全面了解客户情况。
>
> **使用角色与场景：** 销售人员查看客户全貌以辅助跟进；操作人员查看企业资质以处理报关开票；管理层查看交易数据评估客户价值。
>
> **前置条件与触发时机：** 从"我的客户列表"或"公海池"点击客户编号/详情按钮打开，以 Drawer 抽屉形式展示（宽度 1100px）。
>
> **企业资质：** 分三种类型——中国企业（COMPANY_CN）、海外企业（COMPANY_OVERSEAS）、个人（INDIVIDUAL），不同类型展示不同字段布局。企业资质关系到后续的开票、报关等业务，未设置时应显示警告提示引导完善。
>
> **物流地址簿：** 发货人/收货人可维护多条记录，支持增删改查。创建订单时可一键选用地址簿中的记录，避免重复填写。
>
> **数据联动：** 详情页"订单列表"Tab 从 OMS 读取该客户的订单（通过 v2OmsApi.listOrders 按 customerId 查询）；"交易数据"Tab 汇总订单金额计算平均值和完成率；"跟进记录"Tab 读取 ClientPoolLog 展示公海流转日志（认领/释放/转移/自动回收）；"入仓号"Tab 管理该客户的所有入仓号及其状态。

### 6.7 Tab5：入仓号

#### 6.7.1 入仓号表格

| 列 | 说明 |
|-----|------|
| 入仓号 | entryNo |
| 状态 | WarehouseEntryStatus |
| 关联订单 | 关联的订单号 |
| 生成时间 | 入仓号创建时间 |
| 使用时间 | 关联订单或入库的时间 |
| 操作 | 作废（仅"待使用"状态可操作） |

#### 6.7.2 入仓号生成规则

```
格式：{客户shortCode}{3位序号}
示例：A001001, A001002, A001003
```

- `客户shortCode`：客户4位编号
- `3位序号`：从001开始递增

#### 6.7.3 入仓号状态流转

```
待使用 ──→ 已关联 ──→ 已入库
  │
  └──→ 已失效（作废操作）
```

- 待使用 → 已关联：入仓号被关联到订单时
- 已关联 → 已入库：货物实际入库时
- 待使用 → 已失效：执行作废操作时

## 7. 转移跟进

### 7.1 Modal 配置

| 属性 | 值 |
|------|-----|
| 组件类型 | Modal |
| 标题 | 转移跟进 |

### 7.2 表单字段

| 字段名 | 标签 | 组件 | 必填 | 校验规则 | 说明 |
|--------|------|------|------|---------|------|
| 客户 | 客户 | Input | - | disabled | 自动填充当前客户名称，不可编辑 |
| `toSalesId` | 转移给同事 | Select | 是 | 不能为空 | 下拉选择业务员，排除当前 salesId |
| `reason` | 转移说明 | TextArea | 否 | - | 选填，记录转移原因 |

### 7.3 业务规则

- 转移后客户的 `salesId` 更新为目标业务员 ID
- 自动记录一条 ClientPoolLog（action = TRANSFER）
- 转移后客户仍在私海（poolType = PRIVATE）
