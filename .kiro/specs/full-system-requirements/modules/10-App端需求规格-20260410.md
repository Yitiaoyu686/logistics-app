## 1. 设计原则与定位

### 1.1 App 定位

App 是 Web 端的**现场操作伴侣**，面向三类用户：

| 用户 | 核心场景 | 关键词 |
|------|---------|-------|
| **销售** | 外出见客户、电话沟通、随时查单 | 报价、跟单、客户管理 |
| **起运国仓管** | 仓库现场收货、装箱、发货 | 扫码、拍照、称重 |
| **到达国仓管** | 到货入仓、分拣、配送、自提 | 收货、分拣、签收、通知 |

### 1.2 设计原则

| 原则 | 说明 |
|------|------|
| **单手操作** | 仓管场景一手拿货，所有核心操作可单手完成 |
| **大目标区域** | 按钮≥48px、列表行≥56px、字体≥14px |
| **3步内完成** | 扫码→确认→提交，核心操作不超过3步 |
| **离线可用** | 扫码/拍照离线执行，联网后自动同步 |
| **角色隔离** | 登录后只展示该角色的功能，无需切换 |

### 1.3 与 Web 的关系

```
Web 端：订单创建/拆单 · 任务编排 · 财务对账 · 系统配置 · 经营分析
         ↕ 共享 API + 数据库 ↕
App 端：扫码入库 · 库存查询 · 签收确认 · 运价报价 · 订单跟踪
```

## 5. 起运国仓管端

> 角色：WAREHOUSE_CN
> 核心理念：**仓管全程在仓库现场操作，App 覆盖完整仓库流程，不需要回办公室用电脑**

### 5.0 仓库完整工作流

```
快递到仓 → ① 扫码入库 → ② 称重量方 → ③ 生成子运单 → ④ 打印面单
    → ⑤ 贴面单到货物上 → ⑥ 分配库位上架 → ⑦ 装箱/拼柜
    → ⑧ 封箱 → ⑨ 打印箱唛 → ⑩ 等待发运
```

**每一步都在 App 上完成**，通过蓝牙便携打印机现场打印面单和箱唛。

### 5.1 工作台

**顶部**
- 仓库名称 + 切换按钮（广州总仓/深圳集货区）
- 当前操作人姓名
- 蓝牙打印机连接状态（已连接 🟢 / 未连接 🔴）

**统计卡片**（2×2网格）

| 指标 | 说明 | 颜色 |
|------|------|------|
| 今日入库 | 今日完成入库的订单数 | 蓝色 |
| 今日件数 | 今日入库总件数 | 绿色 |
| 今日重量 | 今日入库总重量 kg | 紫色 |
| 异常待处理 | 入库异常+无单快递数 | 红色（>0时） |

**快捷入口**（大按钮区域）
- 📦 扫码入库（最大按钮，高度96px，核心入口）
- 📋 库存查询
- 🏗 装箱管理
- 🔄 调拨管理
- 📦 无单快递
- 🔙 退运查看

**待办列表**
- 待入库订单（按到货时间排序，显示运单号+客户+件数）
- 待装箱（已入库未装箱的货物数）
- 点击进入对应处理页面

### 5.2 扫码入库（一站式流程）

> 核心高频操作。完整流程：扫码 → 称重量方 → 生成子运单 → 打印面单 → 上架。
> 仓管拿着手机+蓝牙打印机，在货物旁一次性完成所有操作。

#### 5.2.1 扫描页面

**布局**
- 全屏相机预览
- 中央扫描对准框（带动画边框）
- 顶部左：闪光灯开关
- 顶部右：手动输入切换（键盘图标）
- 底部统计条：今日已扫 N 件 | 本批次 N 件
- 底部最近记录：✅ SF12345 → MO-xxx 李明 3件

**扫描行为**
- 扫描到条码后震动反馈
- 自动查询订单匹配（<0.5秒）
- 匹配成功进入入库操作页
- 匹配失败进入无单处理页

#### 5.2.2 入库操作页（匹配成功）

> 一页完成：核对→称重→确认→生成子运单→打印→上架

**顶部匹配信息**（绿色卡片）

| 字段 | 说明 |
|------|------|
| ✅ 匹配成功 | 大字绿色标题 |
| 运单号 | MO-20260401-0012 |
| 客户 | 深圳旺达贸易 |
| 路线 | 广州→拉各斯（海运） |
| 收件人 | Amina Yusuf · Lagos |
| 应收件数 | 3 件（已入 1 件，本次第 2 件） |
| 客户申报 | 电子产品 · 申报重量 5kg |

**称重量方区域**

| 字段 | 控件 | 必填 | 说明 |
|------|------|------|------|
| 实际件数 | 数字步进器 | 是 | 默认 1 |
| 实际重量(kg) | 数字键盘 | **是** | 仓管称重后填入 |
| 长(cm) | 数字键盘 | 否 | 量方后填入 |
| 宽(cm) | 数字键盘 | 否 | 量方后填入 |

| 底部 | 件数 · 重量 · 收款方式(预付/到付) |
| 到付金额 | ₦45,000（到付时大字显示） |

#### 6.6.2 签收确认

| 操作项 | 说明 |
|--------|------|
| 签收人姓名 | Input，必填 |
| 签收照片 | 至少1张（货物+签收人） |
| 到付收款 | 到付时必填：金额+方式(现金/转账) |
| 签收备注 | 可选 |
| 确认签收 | 大按钮 → DPN状态变为已签收 |

#### 6.6.3 配送失败

| 操作项 | 说明 |
|--------|------|
| 失败原因 | 必选：无人签收/地址错误/客户拒收/货物破损/其他 |
| 现场照片 | 拍照（可选） |
| 详细说明 | Input |
| 提交 | → 自动通知操作员 |

### 6.7 自提管理

#### 6.7.1 自提列表

**筛选标签**
- 全部 | 待通知 | 已通知 | 已提货

**列表项**

| 区域 | 内容 |
|------|------|
| 头部 | DPN号 + 通知状态标签 |
| 中部 | 客户名 · 电话（拨号） |
| 底部 | 件数 · 重量 · 自提站点 |
| 提货码 | 6位提货码（已通知后显示） |

#### 6.7.2 操作

**发送自提通知**
- 一键发送短信（含自提码+站点地址+营业时间）
- 状态：待通知 → 已通知

**确认提货**
- 客户到仓出示提货码
- 扫码或手动输入验证
- 如有到付款项，录入收款信息
- 确认提货 → 状态变为已提货 → DPN 标记已签收

## 8. 离线与技术约束

### 8.1 离线操作

| 操作 | 离线行为 | 同步策略 |
|------|---------|---------|
| 扫码入库 | 本地暂存扫描记录 | 联网后批量上传 |
| 拍照上传 | 照片存本地 | WiFi下自动上传 |
| 签收确认 | 本地记录 | 联网后同步+推送 |
| 库存查询 | 读取本地缓存（上次同步的数据） | 提示"数据可能不是最新" |
| 运价查询 | 使用本地缓存的费率表 | 提示"离线报价，仅供参考" |

离线状态：
- 顶部显示"离线模式"黄色横幅
- 待同步操作显示"⏳ 待同步"标记
- 联网后自动同步，成功后标记消失

### 8.2 设备要求

| 项目 | 最低要求 |
|------|---------|
| iOS | 15.0+ |
| Android | 10.0+ |
| 存储 | 200MB |
| 相机 | 后置（扫码+拍照） |
| 网络 | 2G/3G/4G/WiFi |

### 8.3 安全

- JWT Token + 刷新机制
- HTTPS 传输加密
- 本地敏感数据加密
- 30天自动登出
