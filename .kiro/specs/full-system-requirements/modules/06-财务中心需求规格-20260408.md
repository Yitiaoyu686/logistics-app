## 1. 费用管理

### 1.1 费用录入（FeeInput.tsx）

> **业务描述**
> 费用录入是财务中心的入口，汇集全链路产生的所有费用。支持手动录入和自动获取(从订单/集装单元/任务自动生成费用草稿)。费用分为应收(向客户收)和应付(付给供应商)两个方向。
> - **角色**: 财务人员(FINANCE)、管理员(ADMIN)
> - **数据来源**: ① TMS的JOB成本(起运国/到达国) ② TMS的订单费用 ③ TMS的DPN成本 ④ 自动获取(系统根据订单/集装/任务自动生成草稿) ⑤ 手动录入
> - **数据去向**: 费用录入后进入审批流程→审批通过后流入应收管理或应付管理→最终汇入毛利表

#### 1.1.1 表单字段

| 字段名 | 字段标识 | 组件类型 | 必填 | 说明 |
|--------|---------|---------|------|------|
| 关联类型 | relatedType | Select | 是 | 选项：ORDER(订单) / UNIT(集装箱) / JOB(任务) / TRANSFER(中转) |
| 关联 ID | relatedId | Select(远程搜索) | 是 | 根据关联类型动态搜索 |
| 关联单号 | relatedNo | Select(远程搜索) | 是 | 与 relatedId 联动 |
| 费用类型 | feeType | Select | 是 | 根据关联类型动态加载选项 |
| 收付方向 | feeDirection | Select | 是 | PAYABLE(应付) / RECEIVABLE(应收) |
| 金额 | amount | InputNumber | 是 | min=0, precision=2 |
| 币种 | currency | Select | 是 | 默认 CNY |
| 汇率 | exchangeRate | InputNumber | 条件 | 仅非 CNY 时显示，precision=4 |
| 供应商名称 | supplierName | Input | 条件 | 仅 feeDirection=PAYABLE 时显示 |
| 客户名称 | customerName | Input | 条件 | 仅 feeDirection=RECEIVABLE 时显示 |

### 1.2 费用审批（FeeApproval.tsx）

> **业务描述**
> 所有费用必须经过审批才能生效。财务主管逐条审批，可通过或驳回。审批通过后费用进入正式的应收/应付管理。
> - **数据影响**: 审批通过→费用状态变为APPROVED→可被应收/应付管理引用; 驳回→需要修改后重新提交

#### 1.2.1 审批 Modal

| 字段名 | 字段标识 | 组件类型 | 必填 | 说明 |
|--------|---------|---------|------|------|
| 审批结果 | approvalResult | Select | 是 | APPROVED(通过) / REJECTED(驳回) |
| 审批意见 | approvalRemark | TextArea | 条件 | 驳回时必填 |

#### 1.2.2 统计卡片

| 指标 | 说明 |
|------|------|
| 待审批 | 笔数 + 金额合计 |
| 已审批 | 笔数 |
| 已驳回 | 笔数 |

## 4. 毛利表（CostReport.tsx）

> **业务描述**
> 毛利表是老板和财务最关注的核心报表，展示每个运单或JOB的收入与成本对比，计算毛利和毛利率。支持按运单明细或JOB汇总两种视图。
> - **计算公式**: 毛利=应收合计-总成本; 毛利率=毛利/应收合计×100%; 总成本=起运国成本+到达国成本(外币×汇率折合CNY)
> - **数据来源**: 应收费用(订单费用中应收方向) + 成本费用(JOB成本起运/到达+DPN成本)
> - **筛选维度**: 月份、空运/海运切换、业务员

### 4.1 GrossProfitRow 字段

| 字段名 | 字段标识 | 说明 |
|--------|---------|------|
| JOB 编号 | jobNo | 任务编号 |
| 集装箱号 | collNo | - |
| 订单号 | orderNo | - |
| 日期 | date | 业务日期 |
| 业务员 | salesPerson | - |
| 发货人 | shipper | - |
| 收货人 | consignee | - |
| 计费体积 | chargeVolume | - |
| 计费重量 | chargeWeight | - |
| 应收(RMB) | receivableRMB | 人民币应收 |
| 已收(NGN) | receivedNGN | 奈拉已收 |
| 已收(USD) | receivedUSD | 美元已收 |
| NGN 汇率 | rateNGN | 奈拉兑人民币汇率 |
| 应收 USD | dueUSD | - |
| USD 汇率 | rateUSD | 美元兑人民币汇率 |
| 应收折合 RMB | dueRMB | = dueUSD × rateUSD |
| 应收总计 | totalReceivable | 应收合计 |
| 代理 | agent | - |
| 运费成本 | freightCost | - |
| 提货成本 | pickupCost | - |
| 送货成本 | deliveryCost | - |
| 包装成本 | packagingCost | - |
| 垫付运费 | advancedFreight | - |
| 起运成本合计 | originCostTotal | = 运费 + 提货 + 送货 + 包装 + 垫付 |
| 进口清关费 | importCustomsFee | - |
| 门到门配送费 | doorDeliveryFee | - |
| 转运费 | transhipmentFee | - |
| 目的港成本(USD) | destCostUSD | - |
| 目的港汇率 | destRate | - |
| 目的港成本(RMB) | destCostRMB | = destCostUSD × destRate |
| 总成本 | totalCost | = originCostTotal + destCostRMB |
| 毛利 | profit | = totalReceivable - totalCost |
| 运输方式 | transportMode | 海运 / 空运 |
| 目的地 | destination | - |

### 4.2 毛利计算公式

| 指标 | 公式 |
|------|------|
| 毛利 | profit = totalReceivable - totalCost |
| 毛利率 | profitRate = profit / totalReceivable × 100% |
| 总成本 | totalCost = originCostTotal + destCostRMB |
| 起运成本合计 | originCostTotal = freightCost + pickupCost + deliveryCost + packagingCost + advancedFreight |
| 目的港成本(RMB) | destCostRMB = destCostUSD × destRate |

### 4.3 视图与操作

| 功能 | 说明 |
|------|------|
| 明细视图 | 逐单展示毛利明细 |
| JOB 汇总视图 | 按 JOB 聚合汇总 |
| 运输方式切换 | 空运 / 海运 |
| 月份选择 | 按月筛选 |
| 业务员筛选 | 按业务员筛选 |
| 导出 Excel | 导出当前视图数据 |

## 6. 应收管理（ReceivableManagement.tsx）

> **业务描述**
> 管理所有应向客户收取的费用。按运单维度统一管理，支持海运/空运筛选。核心功能是跟踪收款进度、登记收款、管理逾期。

> - **数据来源**: 费用管理中方向为"应收"且已审批的费用记录，按运单号汇总
> - **操作**: 收款登记(录入金额/时间/上传凭证)→生成收款记录待审核; 月度统计按空运/海运分别展示; 账龄分析(开发中)

## 8. 提成计算（CommissionCalculation.tsx）

> **业务描述**

> - **数据来源**: 毛利表中按业务员和目的地汇总的票数、毛利、计费重量/体积

### 8.1 提成方案总览

| `PLAN_B_SEA_VETERAN` | 广州海运提成 | 广州海运业务 | 运费总额超基数后分段费率 |

| `PLAN_D_NIGERIA_AIR` | 尼日利亚空运提成 | 尼日利亚空运业务 | 总重量超基数后阶梯单价 |

## 10. 备用金（PettyCashApply.tsx）

> **业务描述**
> 运营过程中的临时紧急支出(码头搬运费/客户接待/海关查验费/快递费等)，金额一般不超过2000元。走备用金申请流程，审批后由财务发放。
