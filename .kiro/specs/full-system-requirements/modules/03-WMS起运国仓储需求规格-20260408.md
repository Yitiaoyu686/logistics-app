## 1. 入库管理 (InboundList)

> **业务描述**
> 客户在电商平台或自有渠道下单后，将货物通过国内快递（顺丰/圆通/中通等）寄到起运国仓库。仓管人员收到快递后扫码入库，系统自动匹配订单运单号。这是物流全链路的第一个实操环节。
> - **角色**: 起运国仓管(WAREHOUSE_CN)、起运国操作(OPS_CN)
> - **三种入库场景**: ① 客户快递入库：客户寄来的快递包裹 ② 调拨到仓入库：从其他仓库调拨来的货物 ③ 退回入库：从到达国退运回来的货物
> - **数据来源**: 订单中心的子运单号+第三方运单号（用于匹配）
> - **数据去向**: 入库成功→更新库存(StockList)→子订单状态变为"已入库"→订单状态更新
> - **匹配逻辑**: 扫描快递单号→在订单的快递包裹列表中查找匹配的 trackingNo→找到则关联到对应子运单
> - **边界**: 同一运单可多次打开继续入库（补录重量/体积等）；取消入库时如已收货需创建退运单

### 1.1 入库场景与菜单结构

### 1.7 客户快递入库不支持手动新增

> **业务规则（2026-04 更新）：** 客户快递入库严格按照"运单维度"执行，所有入库记录必须由 OMS 已创建的子运单驱动，因此**已移除"+新增入库"按钮**。仓管在该页面只能对已存在的入库记录执行扫码 / 补录 / 取消 / 删除操作，不允许手动凭空创建快递入库记录。
>
> 若现场遇到无法匹配到任何运单的快递包裹，应：
> 1. 在"无订单快递"页面手动录入或等待自动写入；
> 2. 待客户线索明确后，匹配现有订单或为客户创建新订单（OMS），然后由系统回写至该快递入库列表。
>
> 对应代码：`InboundList.tsx` 中的 `createModalVisible` 状态及"手动新增客户快递入库" Modal 当前无任何按钮触发，属于历史遗留代码，预留以备未来恢复。

### 1.8 取消入库流程

**流程说明：**

1. **确认是否已收到货**：弹窗询问仓库是否已实际收到该快递
2. **选择取消原因：**
   - **未收到货（5 个选项）**：系统记录原因并直接取消入库记录
   - **已收到货（6 个选项）**：取消入库的同时，系统**自动创建退运单**
3. **退运单自动创建**：当选择"已收到货"取消时，系统自动生成退运单，包含退运快递信息（快递公司、运单号等），流转至退运处理模块

## 2. 库存列表 (StockList)

> **业务描述**
> 展示当前仓库所有在库货物，是仓管日常管理的核心页面。可查看每件货物的库龄（在库天数）、归属订单、状态。
> - **库存状态流转**: 已入库(IN_STOCK)→已分配(ALLOCATED，被选中待装箱)→已装箱(PACKED，装入集装箱/集装号)→已出库(SHIPPED，随JOB发运)→退运中(RETURNED)
> - **数据来源**: 入库操作写入
> - **数据去向**: 装箱操作读取（筛选 IN_STOCK/ALLOCATED 的订单）→退运申请读取→调拨单绑定运单读取
> - **库龄预警**: 超过7天在库显示黄色警告，提醒尽快安排发运

## 3. 任务执行-海运集装箱 (ContainerMgt)

> **业务描述**
> 将库存中的货物按线路和服务类型分组，装入集装箱（海运）或集装号（空运），准备发运。这是起运国仓库的核心出库操作。
> - **角色**: 起运国仓管(WAREHOUSE_CN)
> - **操作流程**: ① 创建线路（线路+服务类型+货物类型） ② 在线路下创建集装箱号/集装号 ③ 从库存中选择运单装入 ④ 封箱 ⑤ 绑定JOB任务 ⑥ 执行任务（=出库发运）
> - **数据来源**: 库存列表中 IN_STOCK/ALLOCATED 状态且线路匹配的运单
> - **数据去向**: 装入集装箱→库存状态变为 PACKED→封箱后绑定 JOB→执行任务后库存状态变为 SHIPPED，子订单状态推进
> - **海运 vs 空运区别**: 海运列名"集装箱号"（如 CSLU0000182）、空运列名"集装号"（如 AK182）；海运默认 40HQ（26000kg/76m³），空运默认 PALLET（1500kg/5m³）
> - **集装箱号格式映射**: 旧格式（AK152）会自动映射为真实集装箱号格式（4字母+7数字）

### 3.1 数据架构

海运任务执行采用三级层次结构：

```
线路分组 (GroupRow)
  └── 集装箱 (ShippingUnit)
        └── 库存订单 (StockRow)
```

- **线路分组（GroupRow）**：按线路维度聚合，展示该线路下所有集装箱及订单
- **集装箱（ShippingUnit）**：具体的集装箱或托盘，承载实际库存订单
- **库存订单（StockRow）**：已入库的订单记录，可分配至集装箱

### 3.2 线路组状态

| 条件 | 状态标识 | 说明 |
|------|---------|------|
| units = 0 | 未生成集装号 | 该线路下无任何集装箱 |
| 存在 LOADING 状态的集装箱 | 待执行 | 有集装箱正在装载中 |
| 全部为 SEALED / SHIPPED / ARRIVED | 已执行 | 所有集装箱已完成装载 |

### 3.3 集装箱状态（ShippingUnitStatus）

| 枚举值 | 中文名称 | 说明 |
|--------|---------|------|
| `EMPTY` | 空闲 | 集装箱已创建，尚未装载货物 |
| `LOADING` | 装载中 | 正在往集装箱中添加货物 |
| `SEALED` | 已封箱 | 装箱完成并已封箱 |
| `SHIPPED` | 已发运 | 集装箱已发运出库 |
| `ARRIVED` | 已到达 | 集装箱已到达目的地 |

### 3.4 创建线路表单

| 字段名 | 中文名称 | 类型 | 必填 | 说明 |

## 7. 退运处理 (ReturnProcess)

> **业务描述**
> 当发生客户取消订单、货物损坏、禁运品、海关退运等情况时，需要将货物退回客户或重新入库。退运涉及费用结算（已付费用中哪些可退、哪些不可退、客户是否需要补缴）。
> - **角色**: 起运国仓管(WAREHOUSE_CN)发起，管理审批
> - **完整流程**: 提交退运申请→审批（通过/驳回）→费用结算（计算应退/应补金额）→执行退运（安排寄回）→完成
> - **费用结算逻辑**: 应退金额 = 客户已付 - 不可退金额 - 待补缴金额。若>0则退款给客户，若<0则客户需补缴，=0则持平。
> - **数据来源**: 库存列表（退运申请时选择运单）、订单取消（OMS取消订单时自动生成）、无订单快递退回
> - **数据去向**: 退运完成→库存状态更新；费用结算→财务中心费用记录

### 7.1 退运来源（ReturnSource）

| 枚举值 | 中文名称 | 说明 |
|--------|---------|------|
| `ORDER_CANCEL` | 订单取消 | 客户取消订单产生的退运 |
| `STOCK_RETURN` | 库存退运 | 从库存发起的退运申请 |
| `PACKING_RETURN` | 装箱退运 | 装箱环节发现问题的退运 |
| `NO_ORDER_RETURN` | 无订单退运 | 无订单快递的退运处理 |
| `MANUAL` | 手动创建 | 人工手动创建的退运单 |

### 7.2 退运类型（ReturnType）

| 枚举值 | 中文名称 | 颜色标签 | 说明 |

| `CUSTOMER_CANCEL` | 客户取消 | `warning` | 客户主动取消退运 |
| `GOODS_ISSUE` | 货物问题 | `error` | 货物损坏/质量问题 |
| `ADDRESS_ERROR` | 地址错误 | `orange` | 收货地址有误 |
| `NO_ORDER` | 无订单 | `default` | 无对应订单的快递退运 |
| `CUSTOMS` | 海关退运 | `error` | 海关扣留/退运 |
| `CLIENT` | 客户退运 | `warning` | 客户要求退运 |
| `OTHER` | 其他 | `default` | 其他原因退运 |

### 7.3 退运状态机（ReturnStatus）

| 状态 | 中文名称 | 说明 |
|------|---------|------|
| `PENDING_APPROVAL` | 待审批 | 退运单提交，等待审批 |
| `APPROVED` | 已通过 | 审批通过 |

**状态流转：**

```
PENDING_APPROVAL → APPROVED（审批通过）
PENDING_APPROVAL → REJECTED（审批驳回）
APPROVED → SETTLING（进入费用结算，需补缴）
APPROVED → SETTLED（费用结算完成，无需补缴或可直接退款）
SETTLING → SETTLED（补缴确认完成）
SETTLED → EXECUTING（开始执行退运）
EXECUTING → COMPLETED（退运完成）
任意状态 → CLOSED（关闭退运单）
```

### 7.4 处置方式（DisposalMethod）

| 枚举值 | 中文名称 | 说明 |
|--------|---------|------|
| `RETURN_TO_CUSTOMER` | 退回客户 | 将货物退回给客户 |
| `RETURN_TO_STOCK` | 退回入库 | 将货物退回仓库重新入库 |
| `DESTROY` | 销毁 | 销毁货物 |

### 7.8 费用结算逻辑

**结算计算公式：**

```
应退金额 = 客户已付金额 - 不可退金额 - 待补缴金额
```

**结算结果分支：**

| 条件 | 结算结果 | 退款标记 | 目标状态 | 说明 |
|------|---------|---------|---------|------|
| 应退金额 > 0 | REFUND（退款） | `REFUNDABLE` | `SETTLED` | 直接完成结算，发起退款 |
| 应退金额 = 0 | EVEN（持平） | — | `SETTLED` | 直接完成结算，无需退款或补缴 |
| 应退金额 < 0 | CUSTOMER_OWES（客户欠款） | `CUSTOMER_OWES` | `SETTLING` | 进入结算中状态，等待客户补缴 |

> 当应退金额 < 0 时，退运单进入 `SETTLING` 状态，等待客户补缴差额后确认，确认后流转至 `SETTLED`。
