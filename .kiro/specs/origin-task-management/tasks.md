# 实现计划

- [x] 1. Mock 数据层与类型定义
- [x] 1.1 定义核心类型和 Mock 数据常量
  - 定义任务管理模块所有 TypeScript 类型：任务（OriginTask）、JOB（TaskJob）、集装号（TaskContainer）、订单货物（ContainerOrderItem）、节点更新记录（NodeUpdateRecord）、节点配置（RouteNodeConfig/NodeConfigItem）、供应商信息、送货公司信息、站点汇总、JOB基础信息等
  - 创建至少 10 条任务 Mock 数据，覆盖待执行、执行中、已完成三种状态
  - 每个 JOB 包含至少 5 个集装号，每个集装号关联至少 3 条订单货物
  - 包含多条线路数据（如 CAN.CHN→LOS.NGN、CAN.CHN→ACC.GHA、SZX.CHN→LOS.NGN）
  - 为每条线路配置 3-6 个不同的运输节点序列（复用基础设置中已有的 NodeType 枚举）
  - 包含部分集装号已标记异常状态的节点更新记录
  - 提供汇总状态计算工具函数：遍历所有集装号取最落后节点，检测是否有异常
  - 提供供应商和送货公司的选项数据（用于表单下拉选择）
  - _Requirements: 6.1, 6.2, 6.3, 6.4, 6.5, 6.6, 4.9_

- [x] 2. 路由控制器与菜单注册
- [x] 2.1 实现任务管理模块的视图切换控制器
  - 创建顶层路由控制组件，管理三个视图状态：列表、创建/编辑表单、JOB详情
  - 维护当前选中的任务ID、JOB ID、是否编辑模式等状态
  - 根据视图状态渲染对应子组件，传递回调函数（创建、编辑、查看详情、返回）
  - 沿用项目已有的 state-driven 视图切换模式（参考现有 JobManager）
  - _Requirements: 1.6, 1.7, 2.6, 2.7_

- [x] 2.2 注册到 App.tsx 菜单系统

  - 替换原有的起运国办任务管理菜单入口，指向新组件
  - 确保角色权限过滤正确（OPS_CN/ADMIN 可见）
  - _Requirements: 1.6_

- [x] 3. 任务列表页
- [x] 3.1 (P) 实现多JOB聚合任务列表表格
  - 使用 Table 组件展示任务列表，列包含：序号、站点/JOB、线路、类型、起运港、目的港、筛选条件、集装号（Tag缩略）、重量Kg、件数、执行状态、操作、更新日期
  - 实现多JOB聚合行显示：同一任务下多个JOB/站点以可展开子行形式展示
  - 集装号列以 Tag 形式缩略展示，超过阈值显示 "...More"
  - 每条任务记录展示汇总运输状态，调用汇总状态计算函数
  - 异常任务在状态列以红色/警告色标识
  - 操作列包含「编辑」「删除」按钮，点击触发回调

- [x] 3.2 (P) 实现筛选与搜索功能
  - 顶部筛选区域：国家下拉（支持全部）、城市下拉（联动国家）、年月日选择器、执行状态下拉
  - 搜索输入框：支持按 JOB号、起运港、司机名称、电话、车牌进行模糊匹配
  - 筛选和搜索实时过滤表格数据（前端 Mock 过滤）

- [x] 3.3 实现列表页操作联动

  - 点击行的「编辑」调用 onEdit 带任务ID切换到编辑表单
  - 点击行的「删除」打开删除确认弹窗
  - 点击集装号区域打开集装号详情弹窗

- [x] 4. 任务创建与编辑表单

  - 选择线路后自动匹配关联的集装号列表，展示集装号总数
  - 编辑模式下加载已有任务数据填充所有表单字段

- [x] 4.2 实现供应商与送货公司表单区域

  - 「送货公司」区域：公司名称选择、运单号/订单号录入、查询电话录入、司机名称录入、司机电话录入、车牌号码录入

- [x] 4.3 实现表单提交与返回逻辑
