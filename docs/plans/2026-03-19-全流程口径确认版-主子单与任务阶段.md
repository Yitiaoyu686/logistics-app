# 全流程口径确认版（主子单与任务阶段）

日期：2026-03-19  
适用范围：Web 端全流程联调（客户中心 -> 订单中心 -> 起运/到达仓办 -> DPN 配送 -> 财务）

## 1. 口径冻结

1. 无单入库可以作为常态入口。
2. 子单生成规则是绝对规则：`1 包裹 = 1 子单`。
3. 无单匹配到已有主单时，必须新建子单，不允许挂到已有子单。
4. 集装号由仓库创建为主，且每个集装号生成一张便单用于打印。
5. 子单可跨集装号，分摊口径按重量或体积。
6. 到达国仓储入库以上游 `Job` 为锚点。
7. DPN 可包含多个子单，但一个子单同一时刻只能属于一个 DPN。
8. 派送失败允许重派，流程为：失败 -> 回仓 -> 重新打包新 DPN -> 重新派送；子单号不变。
9. 运单完成与支付完成是两个独立维度，不互相阻塞；主单完成只看签收维度。
10. 起运国办与到达国办属于同一任务实体的不同阶段，成本需分阶段录入。

## 2. 端到端标准流程（有单）

1. 客户中心创建客户档案。
2. 订单中心创建主单（汇总层）。
3. 起运国办创建任务计划（Job）。
4. 起运国仓入库，每个包裹生成一个子单（执行层）。
5. 起运国仓库存确认后，集中装箱并创建/绑定集装号，输出集装便单。
6. 起运国办推进任务中段节点（发运、清关等）。
7. 到达国办推进同一任务到达阶段节点。
8. 到达国仓按 Job 入库、入库存。
9. 到达侧创建 DPN，执行配送签收。
10. 财务按阶段处理成本提报、审核与收付确认（独立维度）。

## 3. 端到端标准流程（无单常态）

1. 起运仓先收货入库，包裹进入待匹配池。
2. 待匹配池挂单到已有主单。
3. 按每包裹新建子单并进入后续统一流程（任务绑定、到达、DPN、签收）。

## 4. 页面字段统一要求（本轮）

到达国仓储 -> 货物入库列表：

1. 去掉“序号”列。
2. “站点/JOB”改为“任务编号”。
3. 展示与检索统一使用任务编号口径，和起运国办/到达国办任务视图一致。

## 5. 联调验收关键项

1. 任意入库动作后，子单数量必须等于入库包裹数量。
2. 子单绑定集装号时，需可追踪分摊依据（重量/体积）。
3. 子单创建 DPN 后，不可再进入其他活动 DPN。
4. 主单完成仅依赖子单签收聚合，不依赖支付状态。

## 6. 自动化验证命令

在 `server` 目录执行：

1. `npm run verify:v2:sea`：仅验证海运闭环。
2. `npm run verify:v2:air`：仅验证空运闭环。
3. `npm run verify:v2:all`：验证海运+空运全链路，并输出报告：
   - `docs/reports/v2-full-flow-verify-latest.json`
   - `docs/reports/v2-full-flow-verify-latest.md`
4. `npm run audit:v2`：执行数据库一致性审计，并输出报告：
   - `docs/reports/v2-consistency-audit-latest.json`
   - `docs/reports/v2-consistency-audit-latest.md`

在 `client` 目录执行：

1. `npm run typecheck`：前端类型检查（当前已可通过）。
2. `npm run build`：前端构建（vite 构建，可直接用于交付产物）。
3. `npm run build:strict`：严格构建（类型检查 + vite 构建）。

本轮脚本额外覆盖：

1. 子单不能绑定多个“未取消”DPN。
2. 派送失败后，必须“回仓取消旧 DPN”后才允许创建新 DPN 重派。
3. 主单完成与支付完成解耦：签收后先完成主单，再走财务支付流。

## 7. Web 端联调入口（到达国仓储）

页面：

1. `DPN管理`：查看 DPN、派单、标记失败、回仓、签收、查看 DPN 子单与任务历史。
2. `配送列表`：查看配送任务、执行失败/签收动作（失败后回到 DPN 管理执行回仓）。

接口：

1. `GET /api/v2/pod/dpns`
2. `GET /api/v2/pod/dpns/:id`
3. `GET /api/v2/pod/delivery-tasks`
4. `POST /api/v2/pod/delivery-tasks/:id/fail`
5. `POST /api/v2/pod/dpns/:id/return-to-warehouse`
