# Web Demo 数据库优先实施顺序（DB-First）

## 1. 目标与原则

- 目标：不是“页面能看”，而是“关键业务链路可落库、可回放、可审计”。
- 原则：
  - 先打通主链路，再补外围模块。
  - 先海运+空运双线最小闭环，再扩展财务与审核深度。
  - 菜单按现有模块组织；创建/编辑/详情等操作在列表页内完成。

## 2. 当前基础（已具备）

- 数据库已接通：`server/logistics.db`（SQLite）。
- 表结构已存在：订单、子单、入库、库存、运输单元、JOB、DPN、费用、供应商、仓库等主表。
- 后端已挂载核心路由：`/api/orders` `/api/warehouse` `/api/jobs` `/api/delivery` `/api/fees` `/api/system`。
- 海运闭环自动化脚本已存在并可执行。

## 3. 从哪里开始（按阶段）

### Phase 0：业务字典与主数据（必须先做）

对应文档：
- `excel-基础数据.md`
- `excel-国家管理.md`
- `excel-价格体系.md`
- `excel-汇率管理.md`
- `excel-权限管理.md`
- `excel-员工管理.md`

目标：所有下游业务都能“引用主数据”而不是写死枚举。

最小落地项：
1. 汇率改为数据库配置（替代静态返回）。
2. 价格体系按海运/空运分表（或统一表含 transportType）。
3. 国家-城市-站点-仓库形成可查询关系。
4. 费用项目、物流状态、供应商、承运商可配置并可被业务引用。
5. 角色-用户-仓库授权矩阵可落库。

验收：
- 新建订单、建 JOB、录费用时，下拉选项都来自 DB。
- 切换海运/空运，价格与路线来源不同且可追溯。

### Phase 1：双业务线最小业务闭环（核心）

对应文档：
- `customer-order-requirements.md`
- `excel-起运国仓.md`
- `excel-起运国办.md`
- `excel-到达国办.md`
- `excel-到达国仓.md`
- `meeting-notes.md`

目标：同一套菜单骨架下，海运/空运都能完整跑完一条单。

闭环步骤（SEA/AIR 各一条）：
1. 客户下单（主单 + 子单 + 快递包裹）。
2. 起运仓入库（扫描/手工，写入尺寸重量）。
3. 库存与运输单元绑定（海运集装箱/空运货物单元）。
4. 起运国办创建 JOB 并绑定运输单元。
5. 到达国办跟踪 + 创建 DPN。
6. 到达国仓执行配送并签收。
7. 主单状态自动汇总到 COMPLETED。

验收：
- 页面每一步都有真实 INSERT/UPDATE。
- 同一票可追踪完整状态流转（含时间、操作人、节点）。
- 海运与空运数据互不串线。

### Phase 2：财务 + 审核闭环（第二优先）

对应文档：
- `excel-财务管理起运国.md`
- `excel-财务管理到达国.md`
- `excel-审核管理.md`
- `excel-采购管理.md`

目标：业务单据与财务单据一一关联，可审批、可支付、可对账。

最小落地项：
1. 费用录入（ORDER/JOB/UNIT/TRANSFER）。
2. 审核（通过/驳回）与支付状态流转。
3. 应收应付联动订单/JOB/DPN。
4. 退单/退赔触发财务反向动作（取消费用/冲销）。
5. 起运国财务和到达国财务视图分开。

验收：
- 每笔费用都能追溯到业务实体。
- 审核流转后状态一致（页面、API、DB 一致）。
- 可以跑“到付汇率换算”验证场景。

### Phase 3：外围模块接入（最后）

对应文档：
- `excel-我的喵喵.md`
- `excel-用户中心.md`
- `excel-推广管理.md`
- `excel-工作报告.md`
- `excel-服务指南.md`
- `excel-加盟合作.md`

目标：增强演示完整性，但不阻塞主链路验收。

## 4. 建议优先级（你现在就按这个开工）

1. P0-1：汇率/价格/路线/国家站点真库化。
2. P1-1：订单->入库->库存->运输单元->JOB（先海运）。
3. P1-2：复制同链路到空运（仅规则差异）。
4. P1-3：到达国 DPN + 配送签收。
5. P2-1：费用录入 + 审核 + 支付。
6. P2-2：退单退赔 + 财务反向。

## 5. 每阶段必须交付的“可验证物”

- API 冒烟脚本：每个模块至少 1 条创建+1 条状态流转。
- DB 校验 SQL：
  - 主单/子单关系完整。
  - 费用关联实体完整。
  - 状态流转日志完整。
- 场景回放脚本：
  - `SEA-标准单闭环`
  - `AIR-标准单闭环`
  - `退单退赔闭环`

## 6. 风险与控制

- 风险：只改前端菜单，后端字段未统一，导致“看起来能用，落库混乱”。
- 控制：每新增页面功能必须绑定到一个表和一个状态迁移规则，并附验收 SQL。

## 7. 下一步执行建议（立即）

- 第一步就做 `Phase 0` 的“汇率真库化 + 价格体系真库化 + 路线按海空分离查询”。
- 完成后立刻进入 `Phase 1`，先跑通“海运标准单闭环”，再按同模板复制到空运。
