## 2. 结论先行

本轮新增需求不是单纯的页面微调，而是同时影响以下 5 个层面：

1. 物流状态与预测展示
2. 任务创建、执行、审核、通知协同
3. 费用关联、公摊、审批流
4. 到达仓入库口径
5. DPN / 配送 / 自提三类到达侧处理方式

其中，`费用模型`、`审批流`、`到达仓入库口径`、`DPN 与配送关系` 属于结构性改动；  
`颜色区分状态`、`集中装箱到执行任务的界面细节` 属于展示与交互优化。

## 3. 需求影响清单

### 3.1 必须改动的流程与数据模型

| 需求点 | 现有情况 | 影响范围 | 改动级别 | 来源 |
|------|------|------|------|------|
| 费用可关联 `job（公摊）/集装箱号（公摊）/订单号/子单号` | 当前 `fin_fee.fee_level` 支持 `ORDER/SUB_ORDER/JOB/DPN/...`，未明确支持“集装箱号公摊”与分摊明细 | `server/src/database/schema_v2_mvp.sql`、`server/src/routes/v2.ts`、财务录入页 | 高 | `meeting-notes.md` 任务 |
| 多个费用提交 | 当前费用创建是单条记录创建，缺少批量提交与统一提交流程 | 费用接口、费用录入页、审批页 | 中-高 | `meeting-notes.md` 任务 |
| 主管审核，通知操作员，通知账务 | 当前工作流是单节点审批，通过/驳回即结束，没有多节点与通知链 | `wf_instance` / `wf_task`、工作流接口、审批配置页 | 高 | `meeting-notes.md` 任务 |
| 到达国办加订单费用 | 当前订单应收支持订单级费用，但“到达国办公室录入订单费用”的职责边界未单独收口 | 到达国办页面、订单费用页、权限口径 | 中 | `meeting-notes.md` 成本管理、任务 |
| DPN 与配送独立 | 当前 V2 口径更偏向“DPN -> 派送任务”链路，配送任务依附 DPN | `pod_dpn`、`pod_delivery_task`、到达仓储页面 | 高 | `meeting-notes.md` 货物配送、任务 |
| DPN / 配送支持选择到订单或集箱号全部 | 当前 DPN 创建与绑定以 `subOrderIds` 为主，没有“按订单全部”或“按集箱号全部”入口 | DPN 接口、DPN 管理页、配送页 | 高 | `meeting-notes.md` 任务 |
| 到达仓入库可按集箱号，也可按订单号 | 当前冻结文档口径是“到达国仓储入库以上游 Job 为锚点” | 到达仓入库列表、入库接口、状态流转 | 高 | `meeting-notes.md` 货物入库；`2026-03-19-全流程口径确认版` |
| 分批到达、按实际集装号更新状态 | 当前系统已有状态流，但未明确支持“同一业务分批到达”的入库确认口径 | 到达仓入库、物流状态记录、详情时间线 | 中-高 | `meeting-notes.md` 货物入库 |
| 放行后直送客户 | 当前到达侧主流程仍是到仓 -> DPN/配送/签收，没有单独“放行直送客户”状态或按钮 | 到达国办、到达仓、订单详情、状态流转 | 高 | `meeting-notes.md` 货物入库 |
| 物流节点更新可设置预估下一节时间 | 当前 tracking event 以实际事件为主，预测字段没有独立口径 | 物流事件模型、订单详情时间线、基础设置 | 中-高 | `meeting-notes.md` 物流状态、预测设置、任务 |

### 3.2 需要改动的页面与模块

#### 订单中心（OMS）

1. 订单详情页需要继续增强物流状态展示，支持：
   - 更清晰的状态颜色区分
   - 节点预测时间展示
   - 是否对客户展示的标记
2. 订单详情中的费用区需要区分：
   - 起运侧费用
   - 到达侧订单费用
   - 公摊后结果
3. 订单详情需要补充“放行后直送客户”类状态展示。

#### 起运国办（TMS）

1. 任务链路需要明确“办公室创建，仓库执行”的职责边界。
2. 集中装箱到执行任务之间的界面与动作要重整。
3. 任务与费用的关系要加强，支持后续公摊与阶段费用录入。

#### 到达国办 / 到达国仓

1. DPN 管理需要从“当前可派送清单”扩展为：
   - DPN 独立管理
   - 配送独立管理
   - 自提独立管理
2. 配送与自提之间要支持转换。
3. 到达仓入库页要支持：
   - 按集箱号入库
   - 按订单号核实
   - 分批到达
   - 放行后直送客户

#### 财务中心 / 审批中心

1. 费用录入页要支持新增关联对象与公摊口径。
2. 费用审批不能再只是一审一结，需要至少支持“主管审核 -> 后续通知”的流程化能力。
3. 财务表格需求要回收为系统字段与展示规则。

#### 系统设置

1. 物流状态设置需要支持更灵活的节点定义。
2. 可能需要补充预测显示控制字段。
3. 工作流配置页需要支持多节点审批配置，而不是只有单节点实例。

### 3.3 目前主要只是展示优化的项

| 需求点 | 说明 | 改动级别 | 来源 |
|------|------|------|------|
| 物流状态用颜色区分 | 主要是前端展示优化，但要先有统一状态枚举和颜色映射 | 低-中 | `meeting-notes.md` 系统开发 |
| 调整“集中装箱～执行任务”界面细节 | 主要是任务页与仓库页交互优化 | 中 | `meeting-notes.md` 待办 |
| 开发稳定系统供查看 | 偏部署与演示环境，不属于业务模型改动 | 中 | `meeting-notes.md` 系统开发、待办 |

## 4. 当前代码落点与差距

### 4.1 费用与审批

当前 V2 已有以下基础：

1. `fin_fee` 支持费用记录；
2. `wf_instance` / `wf_task` 支持审批实例；
3. `POST /api/v2/finance/fees` 可创建费用；
4. `POST /api/v2/workflow/instances` 与 `POST /api/v2/workflow/tasks/:id/action` 可走一轮审批。

当前差距：

1. 没有“集装箱号公摊”的明确费用层级；
2. 没有费用分摊明细表；
3. 没有多节点审批；
4. 没有“通知操作员、通知账务”的流程结果模型；
5. 没有把“多个费用提交”设计成一批费用的提交动作。

### 4.2 物流状态与预测

当前 V2 已有以下基础：

1. `tms_tracking_event` 可以记录物流事件；
2. 订单 full 接口会组装 `trackingBySubOrder` 时间线；
3. 旧基础设置里已有 `route_logistics_nodes` 概念。

当前差距：

1. 预测时间没有独立字段口径；
2. “是否展示给客户”没有字段；
3. 自定义状态与路线模板的关系还未完全打通到 V2；
4. 前端详情页还没有正式展示预测信息。

### 4.3 到达侧 DPN / 配送 / 自提

当前 V2 已有以下基础：

1. `pod_dpn.delivery_method` 已支持 `SELF_PICKUP / DELIVERY / SATELLITE_STATION`；
2. DPN 创建、绑定子单、派送任务创建、失败、签收已有接口基础；
3. 页面上已有 `DPN管理 / 配送列表 / 自提列表` 菜单入口。

当前差距：

1. `配送列表` 与 `自提列表` 仍有 mock 逻辑；
2. “DPN 与配送独立”的业务口径尚未落实到数据模型；
3. “按订单全部 / 按集箱号全部”发起 DPN 或配送还没有接口能力；
4. 配送与自提互转目前更多是前端演示逻辑，不是正式持久化流程。

### 4.4 到达仓入库

当前差距最明显：

1. 2026-03-19 文档冻结口径是“按 Job 为锚点”；
2. 2026-03-20 新纪要改成“按集箱号，可订单号”；
3. 当前到达仓相关页面仍有较多 mock 展示内容。

因此，到达仓入库是本轮最需要先重新定口径的模块之一。

## 5. 冲突与取舍规则

### 5.1 已发现冲突

#### 冲突 1：到达仓入库锚点

1. 旧口径：到达国仓储入库以上游 `Job` 为锚点。
2. 新口径：仓库入库到达状态可按集箱号，也可按订单号。

处理规则：

1. 按项目规则与本轮任务要求，以最新 `meeting-notes.md` 为准。
2. 旧的 `Job` 锚点保留为查询与追踪维度，不再作为唯一入库入口。

#### 冲突 2：DPN 与配送关系

1. 旧口径：到达侧主链路偏向 `DPN -> 配送任务 -> 签收`。
2. 新口径：`DPN 与配送是独立的`。

处理规则：

1. 目前只能确认“业务上要拆开”；
2. 是否拆成两个独立单据实体，文档尚未完全明确，属于待确认项。

## 6. 待确认项

以下内容在现有文档中仍不够明确，进入实现前建议先确认：

1. `集装箱号公摊` 的分摊规则固定是什么：
   - 按订单平均
   - 按重量
   - 按体积
   - 可配置
2. `DPN 与配送独立` 的真正含义是：
   - DPN 是站点间调度单，配送是末端派送单
   - 还是两者都可直接面向客户
3. `放行后直送客户` 是否仍然需要生成配送单，只是跳过到仓入库。
4. 预测时间是每个节点一个字段，还是允许维护多种预测值。
5. 用户勾选“是否展示”是给内部用户控制，还是按客户维度控制。

## 7. 建议实施顺序

### 第一阶段：先定口径

1. 到达仓入库到底按什么为主入口
2. DPN 与配送是否拆单
3. 费用公摊规则
4. 审批节点顺序与通知对象

### 第二阶段：先补后端能力

1. 扩展费用模型与费用关联对象
2. 增加费用公摊明细
3. 升级审批流为多节点
4. 调整到达侧入库与派送接口
5. 为物流节点预测补字段或结构

### 第三阶段：再改前端页面

1. 订单详情物流状态与费用展示
2. 起运任务页与集中装箱到执行任务界面
3. DPN 管理、配送列表、自提列表正式接 V2
4. 到达仓入库页面重做
5. 财务录入与审批页面升级
