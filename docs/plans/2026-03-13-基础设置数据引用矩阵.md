# 2026-03-13 基础设置数据引用矩阵（DB打通版）

## 1. 基础设置统一主数据

本次将基础设置抽象为统一表 `base_data_items`，并通过 `/api/system/base-data*` 统一管理。

| 数据类型 `dataType` | 说明 | 典型代码 `dataCode` |
|---|---|---|
| `ORDER_SERVICE_TYPE` | 订单服务类型（按空/海运分流） | `LCL_SEA` / `FCL_SEA` / `STANDARD_AIR` / `EXPRESS_AIR` |
| `PAYMENT_METHOD` | 支付方式 | `PREPAID` / `COD` / `CREDIT_CARD` |
| `PAYMENT_CHANNEL` | 支付渠道 | `WECHAT` / `BANK` / `CASH` |
| `CONTAINER_TYPE` | 海运柜型 | `LCL` / `20GP` / `40GP` / `40HQ` |
| `EXPRESS_COMPANY` | 快递公司 | `SF` / `YTO` / `EMS` ... |
| `CARRIER` | 承运人（空运/海运） | `MSK` / `COSCO` / `ET` ... |
| `CARGO_CATEGORY` | 货物分类 | `ELECTRONICS` / `APPAREL` ... |
| `CARGO_TYPE` | 货物属性 | `GENERAL` / `SENSITIVE` / `BATTERY` ... |
| `FEE_TYPE` | 费用类型 | `FREIGHT` / `CUSTOMS_IMPORT` ... |
| `ORDER_REMARK_TAG` | 订单固定备注标签 | `FRAGILE` / `PRIORITY` ... |

## 2. 订单与业务模块引用关系

| 基础数据 | 当前引用模块 | 字段/用途 |
|---|---|---|
| 目的国家/城市（`countries/cities`） | OMS 新建订单、编辑订单 | 国家城市级联、线路代码生成（城市码+国家码） |
| `ORDER_SERVICE_TYPE` | OMS 新建订单、编辑订单 | 服务类型下拉（并按空运/海运过滤） |
| `CONTAINER_TYPE` | OMS 新建订单、编辑订单 | 海运柜型下拉 |
| `PAYMENT_METHOD` | OMS 新建订单、编辑订单 | 支付方式下拉 |
| `PAYMENT_CHANNEL` | OMS 新建订单、编辑订单 | 支付渠道下拉 |
| 汇率币种（`exchange_currencies`） | OMS 新建订单、编辑订单 | 币种下拉 |
| `ORDER_REMARK_TAG` | OMS 新建订单 | 固定备注标签多选 |
| `EXPRESS_COMPANY` | OMS 新建订单、编辑订单 | 包裹预报-快递公司 |
| `CARGO_CATEGORY` | OMS 新建订单、编辑订单 | 包裹预报-货物类别 |
| `CARGO_TYPE` | OMS 新建订单、编辑订单 | 包裹预报-货物属性（用于后端识别敏感货） |
| `CARRIER` | 系统基础设置、到达国仓储配送单、到达国仓储调拨单 | 配送单筛选/创建、调拨单创建第三方物流公司统一使用承运人主数据 |
| `FEE_TYPE` | 系统基础设置、财务费用录入、TMS费用录入（起运港/目的港/订单） | 费用筛选/录入统一费用项目，避免费用口径分裂 |

> 2026-03-13 第二轮补充：
> - `FEE_TYPE` 已接入 `财务中心 -> 费用录入(FeeInput)` 的筛选与录入下拉。
> - `CARRIER` 已接入 `到达国仓储 -> 配送单(DeliveryList/DeliveryCreate)` 的筛选与创建下拉。

> 2026-03-13 第三轮补充：
> - `FEE_TYPE` 已接入 `海运业务 -> 费用录入（起运港 JobCostInputPOL / 目的港 JobCostInputPOD / 订单 OrderFeeInput）`。
> - `CARRIER` 已接入 `到达国仓储 -> 调拨单（DestTransferList / DestTransferCreate）` 的第三方物流公司下拉。
> - 三个 TMS 费用录入页的币种下拉已统一读取汇率管理币种，静态币种仅保留兜底。

## 4. 推荐建设顺序（保证全流程可验证）

1. 先在系统管理完成主数据建档（国家/城市/站点 + 基础设置字典）。
2. OMS 下单引用主数据（本轮已完成核心字段接入）。
3. 起运/到达仓与办公室模块逐步替换硬编码下拉（承运人、费用类型、物流状态）。
4. 财务模块统一引用 `FEE_TYPE` 与汇率表，避免各页面“项目名不一致”。
5. 最后补充“字段血缘检查”（每个业务字段都能追溯到一个主数据来源）。
