
## 场景 2: App 入库 → Web 库存

### 发现并修复 bug

POST `/api/v2/wms/inbounds` 首次返回 500：
```
SqliteError: no such column: "now" — should this be a string literal in single-quotes?
```
**Root cause:** `datetime("now")` 用了双引号，SQLite 把 `"now"` 解释为列名而非字符串字面值。

**Fix:** `server/src/routes/warehouse.ts` POST /inbounds
- 整条 prepare SQL 改为双引号包裹，内部单引号
- 同时补两处缺失逻辑：
  - **自动创建 `wms_stock` 记录**（之前入库不会自动生成库存，Web 库存列表看不到）
  - **自动更新主订单状态**（若所有子单都 INBOUND，主单也变 INBOUND）

### 操作
App 端带 `orderId=e93r6zi55iemnx2q6dr` 跳转 `/task/inbound`，订单信息自动匹配成功（S-2026041300001 / 深圳旺达贸易 / Amina Yusuf），然后 POST 提交入库：
```
POST /api/v2/wms/inbounds
{
  orderId, subOrderId, warehouseId: "wh-gz",
  trackingNo: "SF20260413E2E01",
  pieces: 1, grossWeightKg: 5.8,
  lengthCm: 40, widthCm: 30, heightCm: 20,
  packageCondition: "GOOD", locationCode: "A-05-09"
}

→ { "inboundNo": "IB-20260414-0001" }
```

### App 库存页验证
- 总库存 8 → **9**
- 在库件 5 → **6**
- 总重 92.9 → **98.7 kg**
- 第一条 `S-2026041300001-01 · 深圳旺达贸易 · 1件 5.8kg · 在库 · A-05-09`

### 后端验证
`GET /api/warehouse/stock?keyword=2026041300001` 返回新库存记录（volume_cbm 自动计算为 0.024 m³），子单状态 `sub_status: INBOUND`。

### 结论
✅ **App 入库后 `wms_stock` 自动生成，子单/主单状态联动更新。Web 库存接口与 App 库存页同步。**

## 场景 4: App 签收 → Web 状态

### 操作
App 端 warehouse_us1 对配送任务 `dt-1`（Amina Yusuf · IN_TRANSIT）执行签收：
```
POST /api/v2/pod/delivery-tasks/dt-1/sign
{ "signedBy": "Amina Yusuf", "signPhotoUrls": ["photo1.jpg"], "remark": "客户已签收" }

→ { "success": true }
```

### 后端校验
- `dt-1.task_status`: IN_TRANSIT → **SIGNED**
- `dt-1.signed_at`: `2026-04-14 01:37:54` (自动写入)
- `dpn-1.dpn_status`: PENDING_DISPATCH → **SIGNED**（联动触发器在 sign 接口内实现）

### App 任务流刷新
- **DPN stat: 4 → 3**（dpn-1 已 SIGNED 从活跃列表过滤）
- **配送 stat: 2 → 1**（dt-1 已 SIGNED 从配送 tab 过滤）
- Tab `配送 1`

### 结论
✅ **App 签收后，delivery_task 和 dpn 状态同步更新，App 自身统计即时反映。Web 刷新对应页面也能看到状态变更。**
