## 七、发现的 Bug + 修复

### 🔴 Bug #1: Web 库存列表字段映射错乱（前端）

**现象**：库存列表 19 条但每行运单号/客户/业务员/线路/用户**全部"-"**；统计"在库 0 / 已装箱 0"与实际数据不符。

**根因**：`StockList.tsx` 按 camelCase (`subOrderNo`, `clientName`, `route`) 渲染，但后端返回 snake_case (`sub_order_no`, `customer_name`, `route_code`)。直接 `setStockItems(res.data)` 未做映射。

**修复**：`client/src/pages/wms/origin/StockList.tsx` 新增 `mapStockRow` 映射 snake_case → camelCase。

### 🔴 Bug #2: 到达国入库不在目标仓创建 wms_stock

**现象**：`POST /v2/wms/dest-inbound/:jobId/submit` 只更新 sub_status，没在 `wh-los` 等到达仓建库存记录。导致到达国库存查询空。

**修复**：`server/src/routes/warehouse.ts` 在 dest-inbound 循环内对非 LOST 货物 INSERT `wms_stock(stock_status=IN_STOCK, warehouse_id=<dest>)`。

### 🔴 Bug #3: DPN 派车后不自动派生配送任务

**现象**：`PUT /v2/pod/dpns/:id` 填司机/车牌/dispatch_time 后不自动为每条 `pod_dpn_item` 创建 `pod_delivery_task`。App 配送签收页因此永远无数据。

**修复**：`server/src/routes/delivery.ts` 在 PUT DPN 末尾检测 `hasDispatched` 状态，对每个未派生 task 的绑定运单 INSERT `pod_delivery_task`，并带入收件人信息和司机。

### 🔴 Bug #4: 签收后主订单/库存状态不联动

**现象**：`POST /v2/pod/delivery-tasks/:id/sign` 只更新 task 自己，不级联 sub_order/order/stock，导致主单停留在 ARRIVED 永不 DELIVERED。

**修复**：签收时级联
- `oms_sub_order.sub_status = 'DELIVERED'`
- `wms_stock.stock_status = 'OUTBOUND'`
- 若此主单所有子单都 DELIVERED → `oms_order.order_status = 'DELIVERED'`
- DPN 所有 task 都 SIGNED/FAILED → `pod_dpn.dpn_status = 'COMPLETED'`

### 🔴 Bug #5: DPN 候选运单过滤器状态缺漏

**现象**：`/v2/pod/dpn-candidates` 只匹配 `sub_status IN ('ARRIVED','INBOUND')`，而到达仓入库后 sub_status 已是 `PENDING_DELIVERY`，导致刚入库的运单在 DPN 创建时查不到。

**修复**：过滤器加入 `PENDING_DELIVERY`。

### ⚠️ Bug #6: sign 端点 stock_status 枚举值错误

**现象**：我给 Bug#4 加级联时写了 `stock_status='SHIPPED'`，但 schema CHECK 约束只允许 IN_STOCK/ALLOCATED/PACKED/OUTBOUND/RETURNED/DAMAGED。

**修复**：改为 `OUTBOUND`。

## 八、UX 观察

| # | 页面 | 问题 | 优先级 |
|---|------|------|------|
| 1 | Web 建单弹窗 | 选客户后自动带入收货人 Ada Nwosu/Lagos 地址，但**国家字段空**，用户需手动选尼日利亚。既然知道 Lagos，应该自动识别国家 | 🟡 中 |
| 2 | Web 建单弹窗 | 第一次打开时表单内 Select 的事件处理阻塞，Playwright click 需 30s 才超时，说明 Ant Design `mousedown` 监听和普通 click 事件不互通，对非鼠标自动化极不友好 | 🟢 低 |
| 3 | App 任务流首页 | 装箱中 JOB 卡片进度条大部分显示 0%，和 Web 的实际装箱件数/重量不一致。前端渲染用了静态值而非从后端拉算 | 🔴 高 |
| 4 | Web JOB 详情 | 节点变更记录时间格式不一致：老数据 `2026-04-15 09:00:00`，新推进数据 `2026-04-22T10:00:00Z`。需在 `advanceNode` 里归一化 | 🟡 中 |
| 5 | 全局 | 修改后 nodemon 重启耗时 5-15 秒，偶尔卡死需手动 kill 重建。建议评估是否上 `tsx watch` 提高响应速度 | 🟢 低 |
