## 起运国办费用链路改造方案（Job成本 / 运单费用 / 应收管理）

> 本节为基于当前系统的改造方案，覆盖列表字段、详情页、增删改查、审核与更改申请闭环。

### 1. 业务口径统一

1. Job成本：任务执行过程中的总成本，可关联集装号、主运单、子运单。
2. 运单费用：直接挂在主运单或子运单的费用记录（应收/应付均支持）。
3. 应收管理：面向客户的收款与核销管理，不等同于单条费用明细。

### 2. 费用状态机（按你确认的规则）

1. `DRAFT`：草稿，可编辑、可删除。
2. `PENDING`：已提交待审，锁定主字段，不可直接编辑。
3. `REJECTED`：驳回，可编辑后再次提交。
4. `APPROVED`：审核通过，不可直接编辑，只能发起更改申请。
5. `SETTLED`：已结算/已核销完成。
6. `CANCELLED`：作废（保留审计记录）。

补充流程：
1. 审核完成后如需改动，业务发起 `CHANGE_REQUEST`。
2. 变更审批通过后，系统生成“调整版本”（或调整单），原单保留快照。
3. 调整版本重新进入 `PENDING -> APPROVED` 流程。

### 3. 数据模型改造（P0）

#### 3.1 fee_records（现有主表扩展）

新增字段建议：
1. `biz_no`：业务单号（便于全局检索）。
2. `relation_level`：`JOB | CONTAINER | ORDER | SUB_ORDER`。
3. `job_no`、`container_no`、`order_no`、`sub_order_no`：完整关联链路。
4. `submitter`、`submitted_at`：提交审核信息。
5. `locked_at`：进入审核后的锁定时间。
6. `current_version`：当前版本号（默认1）。
7. `source_fee_id`：来源费用ID（调整单追溯）。
8. `cancel_reason`：作废原因。

索引建议：
1. `(relation_level, job_no, container_no, order_no, sub_order_no)`
2. `(status, fee_direction, created_at)`
3. `(biz_no)` 唯一或半唯一（按业务线加前缀）

#### 3.2 fee_change_requests（新增）

用途：审核通过后的更改申请审批。

核心字段：
1. `id`, `request_no`, `fee_id`, `fee_no`
2. `reason`, `change_payload`（JSON：变更字段前后值）
3. `status`：`PENDING | APPROVED | REJECTED | CANCELLED`
4. `applicant`, `applied_at`
5. `reviewer`, `reviewed_at`, `review_comment`
6. `new_fee_id`（审批通过后生成的新版本费用ID）
7. `created_at`, `updated_at`

索引建议：
1. `(fee_id, status)`
2. `(request_no)` 唯一

#### 3.3 应收闭环表（新增）

1. `receivable_docs`（应收单头）
   - `id`, `receivable_no`, `customer_id`, `customer_name`
   - `currency`, `receivable_amount`, `received_amount`, `unreceived_amount`
   - `due_date`, `aging_days`, `aging_bucket`
   - `status`：`OPEN | PARTIAL | PAID | BAD_DEBT | CANCELLED`
2. `receivable_receipts`（收款记录）
   - `id`, `receivable_id`, `receipt_no`, `receipt_amount`, `receipt_date`, `pay_channel`, `remark`
3. `receivable_writeoffs`（核销明细）
   - `id`, `receivable_id`, `fee_id`, `writeoff_amount`, `writeoff_date`, `operator`

### 4. 接口改造清单（P0）

#### 4.1 费用与审核

1. `POST /api/fees`：创建草稿费用（默认 `DRAFT`）。
2. `PUT /api/fees/:id`：仅 `DRAFT/REJECTED` 可编辑。
3. `DELETE /api/fees/:id`：仅 `DRAFT` 可删除。
4. `POST /api/fees/:id/submit`：提交审核，状态变 `PENDING` 并锁定。
5. `POST /api/fees/:id/approve`：`PENDING -> APPROVED`。
6. `POST /api/fees/:id/reject`：`PENDING -> REJECTED`。
7. `POST /api/fees/:id/cancel`：作废（保留记录）。

#### 4.2 更改申请

1. `POST /api/fees/:id/change-requests`：创建更改申请（仅 `APPROVED` 可发起）。
2. `GET /api/fees/:id/change-requests`：查看申请历史。
3. `POST /api/change-requests/:id/approve`：审批通过并生成新版本费用。
4. `POST /api/change-requests/:id/reject`：审批驳回。
5. `POST /api/change-requests/:id/cancel`：申请人撤销。

#### 4.3 应收管理

1. `POST /api/receivables`：生成应收单。
2. `GET /api/receivables`：应收列表（支持账龄、逾期、客户筛选）。
3. `GET /api/receivables/:id`：应收详情（含收款、核销、催收日志）。
4. `POST /api/receivables/:id/receipts`：登记收款（支持部分收款）。
5. `POST /api/receivables/:id/writeoffs`：执行核销（支持部分核销/多费用核销）。

### 5. 页面与字段改造（列表 + 详情）

#### 5.1 Job成本列表

字段：任务号、集装号、关联主单数、关联子单数、币种、成本总额、待审金额、已审金额、状态、负责人、更新时间。

详情页：
1. 基础信息（任务/线路/站点）
2. 关联链路（集装号-主单-子单）
3. 费用明细与版本记录
4. 审核记录
5. 更改申请记录
6. 操作日志

#### 5.2 运单费用列表

字段：主单号、子单号、费用归属层级、费用类型、费用方向、金额、币种、汇率、提交人、审核人、审核状态、业务日期、更新时间。

详情页：
1. 运单信息
2. 费用项明细
3. 审核轨迹
4. 更改申请轨迹
5. 关联应收/应付单据

#### 5.3 应收管理列表

字段：客户、应收单号、关联主/子单、应收总额、已收、未收、逾期天数、账龄区间、催收状态、责任人、最后跟进时间。

详情页：
1. 应收单头
2. 收款记录
3. 核销明细
4. 账龄变化
5. 催收日志
6. 审计日志

### 6. CRUD与权限规则

1. 新增：业务创建草稿，可反复编辑。
2. 提交：业务提交后进入待审并锁定。
3. 审核：财务审批通过/驳回。
4. 更改：仅审核通过单据允许发起更改申请。
5. 删除：仅草稿允许删除；其他状态只允许作废。
6. 结算：财务登记收款并核销后转 `SETTLED`。

角色建议：
1. 业务：创建、编辑草稿、提交、更改申请。
2. 财务：审核、收款、核销、作废。
3. 主管：审批规则配置、关账、反关账（受控）。

### 7. 分期实施

#### P0（先落地）

1. 状态机改造（含提交审核、审核后更改申请）。
2. 费用主表扩展 + 更改申请表。
3. Job成本/运单费用列表字段与详情页补齐。
4. 应收单 + 收款 + 核销最小闭环。

#### P1（增强）

1. Job成本自动分摊（按重量/体积/票数）。
2. 多级审批规则（金额阈值、费用类型、业务线）。
3. 任务关账后禁止直接改历史费用，仅允许调整单。
4. 账龄与催收策略自动化。

### 8. 验收标准

1. 审核前可修改，审核后不可直改，只能走更改申请。
2. 任一费用可追溯到任务、集装号、主单、子单。
3. 审批轨迹和更改轨迹完整可审计。
4. 应收支持部分收款、部分核销，金额口径与费用一致。
5. 列表汇总、详情金额、财务报表三者一致。
