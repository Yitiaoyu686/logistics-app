## 二、海运业务流程逐环节对比

### 完整业务流程

```
订单创建 → 快递入库 → 库存管理 → 装箱(集装箱) → 办单订舱 →
报关出口 → 发运离港 → 在途追踪 → 到港 → 进口清关 →
到达国入库 → DPN派送/自提 → 配送签收 → 费用结算
```

## 四、差异严重程度汇总

### 🔴 严重缺失（影响完整业务流程）

| # | 缺失项 | 影响 |
|---|--------|------|
| 1 | **OPS_CN 起运国操作角色+全部页面** | 无法在App完成订舱、报关、节点更新等核心操作 |
| 2 | **OPS_US 到达国操作角色+全部页面** | 无法在App完成清关、到港登记等操作 |
| 3 | **JOB成本录入** (POL+POD+OrderFee+DPN) | 无法在App录入任何运输成本 |
| 4 | **物流节点管理** (NodeUpdate) | 无法在App更新物流轨迹 |
| 5 | **财务中心** (17个页面) | 无法在App处理任何财务业务 |

### 🟡 部分缺失（功能弱化但不阻断）

| # | 缺失项 | 影响 |
|---|--------|------|
| 6 | 订单拆单功能 | App端只能创建/查看订单，不能拆单 |
| 7 | 工作台仪表盘 | App端仅有简化待办列表 |
| 8 | 经营分析 (5个页面) | App端无数据分析能力 |
| 9 | 客户公海池管理 | App端无公海池回收/分配功能 |
| 10 | 统计卡片 (装箱页) | App端无待执行/已执行等统计 |
| 11 | 装箱-线路创建 | App端装箱不包含线路创建 |

### 🟢 基本对齐

起运国仓储入库/库存/装箱核心操作、调拨、退运、无单快递、到达国仓储入库/库存/DPN/配送/自提等日常仓管操作基本对齐。

## 五、技术实现差异

| 维度 | Web | App |
|------|-----|-----|
| 框架 | React + Ant Design | React Native + Expo |
| Mock数据 | 分散在各模块文件(内联+独立文件) | API调用(失败则空) |
| 数据源 | 本地Mock (~200KB legacy data) | API请求(需后端) |
| 状态管理 | useState+useMemo | useState+useContext(BusinessLine) |
| 路由 | 状态驱动(activeMenuKey+activeTabKey) | expo-router 文件路由 |
| 样式 | Ant Design + 内联style | StyleSheet + theme tokens |
| 图标 | @ant-design/icons | @expo/vector-icons/Ionicons |

## 六、建议优先级

如果要在App端补齐海运业务流程，建议按以下优先级：

**P0 - 阻断操作**：
1. OPS_CN 起运国操作面板（任务管理 + 节点更新）
2. JOB成本录入（至少JOB级别）

**P1 - 高频需求**：
3. OPS_US 到达国操作面板
4. 订单拆单功能

**P2 - 体验提升**：
5. 工作台统计卡片
6. 装箱统计摘要
7. 客户公海池

**P3 - 非移动端优先**：
8. 财务中心（适合PC端操作）
9. 经营分析（适合大屏查看）
10. 系统管理（管理员专用，频次低）
