## 一、背景

用户反馈「仓管的一些业务需要仓管创建，但 APP 端没有创建入口」。对比 Web 与 App 仓管角色（WAREHOUSE_CN / WAREHOUSE_US）的创建/写入动作后，识别出以下缺口：

### Web vs App 仓管创建入口（MCP 实测）

| 业务 | Web 创建入口 | App 端状态 | 优先级 |
|------|----------|---------|------|
| 创建集装号 | ✅ 任务执行 | ✅ `packing.tsx` 已有 | ✓ |
| 创建调拨单 | ✅ 调拨管理 | ✅ `transfer.tsx` 已有 | ✓ |
| 新增无订单快递 | ✅ 无订单快递 | ✅ `no-order-express.tsx` 已有 | ✓ |
| 创建 DPN 任务 | ✅ DPN管理 | ✅ `dpn-create.tsx` 已有 | ✓ |
| **新建退运单** | ✅ 退运处理 | ❌ `return-process` 只读 | 🔴 高 |
| **库存退货申请** | ✅ 库存列表行操作 | ✅ `stock.tsx` 已有（已实现） | ✓ |
| 创建线路 | ✅ 任务执行「创建线路」 | ❌ 无 | 🟡 暂缓 |

## 二、本次改动

### 2.1 新建退运页（主要功能）

**新增文件**: `app/app/task/return-create.tsx`

**交互流程**:
```
1. 🔍 扫码/手动输入子单号/运单号 → [查询]
      ↓
   自动查 warehouse/stock?keyword=xxx，找到库存记录展示
      （主单/客户/件数/重量/库位/状态）
      ↓
2. ❓ 选择退运原因:
   - 客户取消 / 货物问题 / 地址错误 / 其他
   + 补充说明（可选）
      ↓
3. 📦 选择货物处置方式:
   - 退回客户 / 退回入库 / 销毁
      ↓
4. 📮 如"退回客户"：填收件信息（姓名/电话/地址）
      ↓
5. [提交退运申请]
      ↓
   POST /warehouse/stock/:id/return
   {
     reason: "客户取消 · 临时不发货",
     disposalMethod: "RETURN_TO_CUSTOMER",
     recipientName, recipientPhone, recipientAddress
   }
      ↓
   - wms_stock.stock_status = 'RETURNED'
   - oms_sub_order.sub_status = 'RETURN_APPLIED'
   - wms_inbound_order.remark 追加备注
```

**状态要求**: 只对 `stock_status = IN_STOCK` 的库存允许退运（由后端状态机兜底）。

### 2.2 退运处理页（解除只读）

**修改文件**: `app/app/task/return-process.tsx`

1. 移除顶部 "只读" 标签
2. 右上角新增「+ 新建」按钮 → 跳转 `/task/return-create`
3. 提示文案改为"发现库存异常或客户取消时可直接新建退运单"

### 2.3 库存退货（无需新增，原有）

核查发现 `app/app/task/stock.tsx` 已在库存详情弹窗内实现"申请退运"入口（`IN_STOCK` 且非到达国时显示），直接调用 `warehouseApi.applyReturn`。此入口与新建退运页并存，两条路径都可达：

- 从**库存管理**进入 → 选中一条库存 → 详情内「申请退运」
- 从**退运处理**进入 → 右上角「+新建」 → 先搜库存再退运

### 2.4 创建线路（评估后暂缓）

**决策**: App 端暂不做「创建线路」入口。

**理由**:
- 线路是**系统管理配置项**（需选国家/城市/业务线/时效/承运人等多级下拉），非仓管日常操作
- App 定位是手机端执行工具，Web 是管理工具，职责分开更清晰
- Web 端「任务执行/创建线路」功能可覆盖
