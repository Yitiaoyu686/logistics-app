## 二、退运触发场景（5种）

| 场景 | 触发入口 | 货物当前状态 | 是否涉及费用结算 |
|------|---------|------------|----------------|
| **客户取消订单** | 订单列表 → "取消订单" | 未入库 或 已入库未出库 | 已付款→结算退款；到付→可能需补缴 |
| **库存内退运** | 起运国库存列表 → "退运" | 在库（未装箱） | 同上 |
| **装箱后退运** | 需先从集装号拆出 → 再退运 | 已装箱（先拆后退） | 同上 |
| **无订单快递退回** | 无订单快递 → "退回" | 无主包裹在仓 | 无（未产生订单和费用） |
| **到达国退运** | 暂不支持 | — | — |

## 三、统一退运流程

### 3.1 主流程

```
① 触发退运（各入口）
      ↓
② 创建退运单（填写退运信息）
      ↓
③ 退运审批（RETURN_APPROVE，2节点）
      ↓ 通过                       ↓ 驳回
④ 费用结算                      退回修改 / 关闭退运单
      ↓
⑤ 结算完成 → 执行退运（放货）
      ↓
⑥ 货物处置（退回客户 / 退回入库 / 销毁）
      ↓
⑦ 退运完成（关闭退运单，更新订单/子单状态）
```

### 3.2 费用结算子流程（核心）

```
退运审批通过
      ↓
系统自动列出该退运单关联的所有费用条目
      ↓
财务逐条标记每笔费用的退款属性：
  ├── ✅ 可退（退还客户） — 运费(未发运)、配送费(未配送)等
  ├── ❌ 不可退（已消费） — 打木架费、仓储费、入库操作费、包装费等
  └── ⚠️ 待补缴（客户欠款） — 到付场景仓库已垫付、客户未付的费用
      ↓
系统自动汇算：
  应退金额 = 客户已付金额 - 不可退费用 - 待补缴费用
      ↓
  结果 > 0 → 退款给客户（财务确认退款 + 上传凭证）
  结果 = 0 → 直接结清（无需退款也无需补缴）
  结果 < 0 → 客户需补缴（通知客户付款 → 确认到账 → 才能放货）
      ↓
结算完成 → 进入执行退运环节
```

**关键原则：未结清费用不能放货退运。**

## 四、退运单数据结构

### 4.1 基本信息

| 字段 | 说明 |
|------|------|
| 退运单号 | RTN-{date}-{seq} |
| 退运来源 | ORDER_CANCEL / STOCK_RETURN / PACKING_RETURN / NO_ORDER_RETURN |
| 关联主单号 | 主订单号（无订单快递场景为空） |
| 关联子单号 | 子单号列表（可多个） |
| 业务线 | SEA / AIR |
| 客户 | 客户名称 |
| 路线/目的地 | 路线编码 |
| 集装号 | 如已装箱，记录原集装号 |
| 货物信息 | 件数、重量、品名 |
| 退运类型 | CUSTOMER_CANCEL / GOODS_ISSUE / ADDRESS_ERROR / NO_ORDER / OTHER |
| 退运原因 | 文字描述 |
| 货物处置方式 | RETURN_TO_CUSTOMER / RETURN_TO_STOCK / DESTROY |

### 4.2 退运状态

| 状态 | 说明 |
|------|------|
| PENDING_APPROVAL | 待审批 |
| APPROVED | 审批通过，待费用结算 |
| SETTLING | 费用结算中（财务处理） |
| SETTLED | 费用已结清，待执行退运 |
| EXECUTING | 执行退运中（货物处置） |
| COMPLETED | 退运完成 |
| REJECTED | 审批驳回 |
| CLOSED | 关闭（取消退运） |

### 4.3 费用结算信息

| 字段 | 说明 |
|------|------|
| 客户已付总额 | 从订单支付记录汇总 |
| 不可退费用总额 | 财务标记的已消费费用合计 |
| 待补缴费用总额 | 财务标记的客户欠款合计 |
| 应退金额 | = 已付 - 不可退 - 待补缴（可正可负可零） |
| 结算状态 | NONE / PENDING / CUSTOMER_OWES / REFUNDING / SETTLED |
| 结算明细 | 每笔费用的标记（可退/不可退/待补缴）列表 |

### 4.4 退款/补缴信息

| 字段 | 说明 |
|------|------|
| 退款方式 | ORIGINAL(原路退回) / BANK(银行转账) / OFFLINE(线下) |
| 退款金额 | 实际退款金额 |
| 退款凭证 | 上传图片 |
| 退款操作人 | 财务人员 |
| 退款时间 | |
| 补缴金额 | 客户需补缴的金额（结算为负时） |
| 补缴状态 | NONE / PENDING / PAID |
| 补缴凭证 | 客户付款凭证 |

## 五、各场景详细流程

### 5.1 场景一：客户取消订单

**触发**：订单列表 → 点击"取消订单"

**操作步骤**：
1. 弹窗填写：退运原因、货物处置方式（退回客户/退回入库/销毁）
2. 系统自动创建退运单（来源=ORDER_CANCEL），关联主单号和所有子单
3. 退运审批（RETURN_APPROVE）
4. 审批通过 → 退运单状态变为 SETTLING，流转到财务
5. 财务在退运处理页面的"费用结算"操作中：
   - 看到该订单所有费用条目
   - 逐条标记：可退 / 不可退 / 待补缴
   - 系统汇算结算金额
6. 如需客户补缴 → 通知客户 → 客户付款 → 上传凭证确认
7. 如需退款 → 财务操作退款 → 上传退款凭证
8. 结算完成 → 执行退运 → 货物处置 → 退运完成
9. 订单状态更新为"已取消"，子单状态更新

**联动影响**：
- 订单状态 → 已取消
- 子单状态 → 已退运
- 库存 → 移出（如在库）
- 集装号 → 拆出（如已装箱）
- 支付状态 → 已退款/部分退款

### 5.2 场景二：库存内退运

**触发**：起运国库存列表 → 点击子单的"退运"

**操作步骤**：
1. 弹窗填写：退运原因、退运类型、货物处置方式
2. 系统创建退运单（来源=STOCK_RETURN），关联该子单和主单
3. 后续流程同场景一的步骤3-9

**联动影响**：
- 该子单状态 → 已退运
- 该子单从库存移出
- 主单状态重新聚合（如果所有子单都退了，主单=已取消）
- 费用结算按该子单关联的费用进行

### 5.3 场景三：装箱后退运

**触发**：需手动先从集装号中拆出

**操作步骤**：
1. 集中装箱页面 → 从集装号中移除对应子单（前置操作）
2. 子单状态从"已装箱"回到"在库"
3. 然后在库存列表中对该子单点"退运" → 走场景二流程

**联动影响**：
- 集装号的件数/重量/体积更新
- 子单状态：已装箱 → 在库 → 已退运

### 5.4 场景四：无订单快递退回

**触发**：无订单快递列表 → 点击"退回"

**操作步骤**：
1. 弹窗填写：退回原因
2. 创建退运单（来源=NO_ORDER_RETURN，无关联订单）
3. 退运审批（简化，因无费用结算）
4. 审批通过 → 直接执行退回 → 退运完成
5. 无订单快递状态更新为"已退回"

**联动影响**：
- 无订单快递记录状态 → RETURNED
- 不涉及费用和退款

## 六、页面操作设计

### 6.1 退运处理页面（起运国仓储 → 退运处理 tab）

**统计行**：
待审批 | 审批中 | 待结算 | 待补缴 | 执行中 | 已完成 | 已驳回

**筛选**：
- 退运来源（全部/客户取消/库存退运/装箱退运/无订单退回）
- 退运状态
- 退款状态

**列表列**：
退运单号 | 创建时间 | 退运来源 | 订单信息 | 业务线 | 客户 | 货物信息 | 退运类型 | 退运状态 | 费用结算状态 | 退款状态 | 处理人 | 操作

**操作按钮（按状态显示）**：
| 退运状态 | 可用操作 |
|---------|---------|
| 待审批 | 审批（通过/驳回）、详情 |
| 审批通过(待结算) | 费用结算、详情 |
| 结算中 | 查看结算、详情 |
| 待补缴 | 确认补缴、详情 |
| 待执行 | 执行退运、详情 |
| 执行中 | 完成退运、详情 |
| 已完成 | 详情 |

### 6.2 费用结算弹窗/Drawer（财务操作）

**头部信息**：退运单号、客户、订单号、退运原因

**费用明细表格**：
| 费用编号 | 费用项目 | 金额 | 币种 | 汇率 | 折合CNY | 支付状态 | 退款标记 | 操作 |
|---------|---------|------|-----|------|--------|---------|---------|------|
| FEE-xxx | 运费 | 1200 | CNY | 1 | 1200 | 已付 | 可退 ✅ | 切换 |
| FEE-xxx | 打木架费 | 200 | CNY | 1 | 200 | 已付 | 不可退 ❌ | 切换 |
| FEE-xxx | 仓储费 | 150 | CNY | 1 | 150 | 未付(垫付) | 待补缴 ⚠️ | 切换 |

**汇总区域**：
```
客户已付总额：¥1,400.00
不可退费用（已消费）：¥200.00
待补缴费用（客户欠款）：¥150.00
───────────────────
应退金额：¥1,050.00  （= 1400 - 200 - 150）
```

**操作按钮**：确认结算 → 生成退款单/补缴通知

### 6.3 退款操作（财务中心 → 往来账款）

退运结算完成后，如有退款：
- 在应收账款中生成一条**负向记录**（退款单），金额为负
- 财务在应收账款页面操作"确认退款" → 选择退款方式 → 上传退款凭证
- 退款确认后 → 更新退运单退款状态、订单支付状态

如需客户补缴：
- 在应收账款中生成一条**正向记录**（补缴单），状态为待收
- 走正常的收款登记流程（客户付款 → 上传凭证 → 财务确认）
- 补缴确认后 → 更新退运单结算状态 → 可以放货

### 6.4 订单详情联动

退运完成后，在订单详情中：
- 基本信息区显示"已取消"状态 + 退运标记
- 应收明细中显示退款记录（负向金额）
- 已付款记录中显示退款凭证
- 总计核算更新：应收总额不变，已退款金额单独显示

## 七、状态联动汇总

| 退运操作 | 退运单状态 | 订单状态 | 子单状态 | 库存 | 集装号 | 支付状态 |
|---------|-----------|---------|---------|------|-------|---------|
| 创建退运 | 待审批 | 不变 | 不变 | 不变 | 不变 | 不变 |
| 审批通过 | 待结算 | 不变 | 不变 | 不变 | 不变 | 不变 |
| 结算完成(需退款) | 待执行 | 不变 | 不变 | 不变 | 不变 | 退款中 |
| 结算完成(需补缴) | 待补缴 | 不变 | 不变 | 不变 | 不变 | 不变 |
| 补缴完成 | 待执行 | 不变 | 不变 | 不变 | 不变 | 不变 |
| 执行退运 | 执行中 | 不变 | 退运中 | 移出 | 拆出(如有) | 不变 |
| 退运完成 | 已完成 | 已取消(全退) / 不变(部分退) | 已退运 | 已移出 | 已拆出 | 已退款 |

## 八、审批流程复用

| 环节 | 使用的审批流程 | 说明 |
|------|-------------|------|
| 退运审批 | RETURN_APPROVE（2节点，已启用） | 仓管/运营提交 → 主管审批 |
| 退款审核 | 复用 FEE_APPROVE（2节点，已启用） | 通过费用审批通道处理退款确认 |
| 补缴确认 | 复用收款登记流程 | 客户付款 → 上传凭证 → 财务确认 |
