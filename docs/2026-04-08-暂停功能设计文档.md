# 暂停功能设计文档

> 更新日期：2026-04-08

---

## 一、功能概述

系统支持对**订单（主订单）**、**子运单**、**任务（JOB）**三个层级进行暂停操作。暂停后相关下游操作被冻结，恢复后还原到暂停前的状态继续流转。

---

## 二、暂停触发场景

| 原因分类 | 具体场景 |
|---------|---------|
| 客户要求 | 临时取消发货、修改收货地址、调整货物内容 |
| 付款问题 | 客户未付款、欠费、费用争议待解决 |
| 海关/合规 | 海关查验通知、单证不齐需补充、禁运品排查 |
| 货物问题 | 破损需重新包装、短缺需补货、错发需更正 |
| 内部调度 | 仓库爆仓暂缓入库、船期/航班变更、任务重新分配 |

---

## 三、各层级暂停规则

### 3.1 订单暂停（主订单）

**操作入口：** 订单列表 → 操作列 → "暂停"按钮

**触发条件：** 订单状态不是 `已完成`、`已取消`、`已暂停` 时可暂停

**暂停时：**
- 必须选择暂停原因（下拉选择）
- 可填写备注说明
- 记录暂停前的原始状态，用于恢复

**暂停后影响：**

| 操作 | 影响 |
|------|------|
| 子运单 | 全部自动暂停 |
| 快递入库 | 禁止该订单的快递入库确认 |
| 装箱/装柜 | 禁止添加到集装箱/集装号 |
| 费用录入 | 允许查看，禁止新增 |
| 收款登记 | 禁止 |
| 任务绑定 | 禁止关联到任务 |
| 出库发运 | 禁止 |
| 编辑订单 | 禁止 |
| 取消订单 | 禁止（先恢复再取消） |

**恢复操作：** 点击"恢复"按钮，订单还原到暂停前的状态

**状态标识：** 红色 `已暂停` Tag

### 3.2 子运单暂停（单票暂停）

**操作入口：** 订单详情 → 子运单列表 → 操作列 → "暂停"

**触发条件：** 子运单状态不是 `已签收`、`已取消`、`已暂停`

**暂停后影响：**

| 操作 | 影响 |
|------|------|
| 主订单 | 不影响（其他子运单继续流转） |
| 该子运单入库 | 禁止入库确认 |
| 装箱 | 禁止添加到集装箱/集装号 |
| 已装箱的 | 标记异常，提示需移出 |
| 费用 | 该子运单相关费用冻结 |
| 配送/自提 | 禁止创建配送单或自提单 |

### 3.3 任务暂停（JOB暂停）

**操作入口：** 起运国办/到达国办 → 任务管理 → 操作列 → "暂停"

**触发条件：** 任务状态不是 `已完成`、`已暂停`

**暂停后影响：**

| 操作 | 影响 |
|------|------|
| 任务执行（出库） | 禁止执行出库 |
| 添加订单 | 禁止往集装箱/集装号里装货 |
| 节点更新 | 禁止推进节点状态 |
| 费用录入 | JOB成本禁止新增 |
| 关联子运单 | 不自动暂停（货物已在箱里） |
| 到达国入库 | 禁止 |

## 四、暂停原因选项

| 选项值 | 显示文本 |
|-------|---------|
| `CUSTOMER_REQUEST` | 客户要求暂停 |
| `PAYMENT_ISSUE` | 付款问题 |
| `CUSTOMS_INSPECTION` | 海关查验 |
| `DOCUMENT_INCOMPLETE` | 单证不齐 |
| `CARGO_ISSUE` | 货物问题（破损/短缺） |
| `DISPATCH_ADJUSTMENT` | 内部调度调整 |
| `OTHER` | 其他 |

---

## 五、状态流转

### 5.1 订单状态流转

```
正常流转状态（等待入库/已入库/已发运/运输中/...）
    ↓ 暂停
  已暂停（SUSPENDED）
    ↓ 恢复
  还原到暂停前的状态
```

### 5.2 任务状态流转

```
待执行（PENDING） / 执行中（IN_PROGRESS）
    ↓ 暂停
  已暂停（SUSPENDED）
    ↓ 恢复
  执行中（IN_PROGRESS）
```

## 六、权限控制

| 操作 | 权限要求 |
|------|---------|
| 暂停订单 | 业务员、仓管、运营均可操作 |
| 恢复订单 | 需主管或更高权限审批（Demo 中暂无审批流程） |
| 暂停任务 | 操作站点仓管、起运国办运营 |
| 恢复任务 | 同暂停权限 |

## 七、数据存储

### 7.1 暂停记录

暂停操作记录以下信息：

| 字段 | 说明 |
|------|------|
| `targetId` | 被暂停对象的 ID |
| `targetType` | ORDER / SUB_ORDER / TASK |
| `originalStatus` | 暂停前的原始状态 |
| `suspendReason` | 暂停原因 |
| `suspendRemark` | 备注说明 |
| `suspendedAt` | 暂停时间 |
| `suspendedBy` | 操作人 |
| `resumedAt` | 恢复时间（恢复后填写） |
| `resumedBy` | 恢复操作人 |

### 7.2 当前实现方式

Demo 原型中使用 `localStorage` 持久化暂停状态：
- Key: `order_suspend_store`
- Value: `{ [orderId]: { originalStatus, reason, suspendedAt } }`

任务暂停直接修改内存中的 task 对象状态。

## 八、界面设计

### 8.1 暂停按钮

- 位置：列表操作列
- 样式：橙色文字链接 `暂停`
- 条件：非终态（已完成/已取消/已暂停）时显示

### 8.2 恢复按钮

- 位置：列表操作列（替代暂停按钮）
- 样式：绿色文字链接 `恢复`
- 条件：仅 `已暂停` 状态时显示

### 8.3 暂停弹窗

- 标题：暂停订单 / 暂停任务
- 表单：暂停原因（必填下拉）+ 备注说明（选填）
- 确认按钮：橙色"确认暂停"

### 8.4 状态标识

- 颜色：红色 Tag `已暂停`
- 位置：列表状态列、详情页顶部状态栏
