# 喵喵国际物流系统 — 业务闭环需求理解（v2）

> 基于实际页面截图 + 业务方修正，覆盖总体架构→业务闭环→跨模块衔接→数据流转

---

## 一、系统定位与总体架构

### 1.1 系统定位

面向**中非跨境物流货代公司**的多组织 SaaS 平台，覆盖从中国（广州/深圳/香港）发往非洲（尼日利亚拉各斯/阿布贾、加纳阿克拉）的海运和空运拼柜业务。

**本质**：一个**多组织 SaaS 系统**——每个站点是一个独立的业务单元，只看自己的数据，管理自己的业务。站点之间通过 DPN 进行跨站协同调度。

**核心价值**：将分散在 Excel 和多系统中的客户管理、订单、仓储、运输、财务业务整合到统一平台，实现数据闭环和角色协同。

### 1.2 多组织体系

```
系统（SaaS 平台）
  └── 站点（组织单元，数据隔离）
       ├── 浦东站点（起运国）
       ├── 白云区站点（起运国）
       ├── 福田区站点（起运国）
       ├── 海珠区站点（起运国）
       ├── 东莞站点（起运国）
       ├── 阿克拉站点（到达国·加纳）
       ├── 哈科特港站点（到达国·尼日利亚）
       ├── 伊科贾站点（到达国·尼日利亚）
       ├── 阿布贾站点（到达国·尼日利亚）
       └── 卡诺站点（到达国·尼日利亚）
```

**站点管理入口**：系统管理 → 组织管理（站点）
- 每个站点下可配置仓库（起运国仓库/到达国仓库/中转仓库）
- 用户可分配到一个或多个站点
- 业务数据（订单、库存、任务、费用）按站点隔离

### 1.3 四域架构

```
┌─────────────────────────────────────────────────────────────┐
│  综合协同  │  海运业务  │  空运业务  │  系统管理              │
├───────────┼────────────┼────────────┼────────────────────────┤
│ 工作台     │ 工作台      │ 工作台      │ 组织管理（站点）        │
│ 财务中心   │ 客户中心    │ 客户中心    │ 用户管理               │
│  ├费用与成本│ 订单中心    │ 订单中心    │ 角色权限               │
│  ├往来账款  │ 起运国仓储  │ 起运国仓储  │ 基础设置（10个子Tab）   │
│  ├备用金    │ 起运国办    │ 起运国办    │ 流程管理               │
│  ├提成与薪资│ 到达国办    │ 到达国办    │ 消息通知               │
│  └财务报表  │ 到达国仓储  │ 到达国仓储  │                        │
│ 经营分析   │            │            │                        │
└───────────┴────────────┴────────────┴────────────────────────┘
```

- 海运和空运**共享同一套页面结构**，通过业务域切换区分数据（S-/A-前缀）
- 综合协同域是**跨业务线汇总视角**，财务和分析不区分海运/空运
- 系统管理域管理**平台级配置**，包括组织、用户、基础数据

## 二、核心业务主流程闭环

### 2.1 全流程总览

```
 SALES        WAREHOUSE_CN        OPS_CN/OPS_US      WAREHOUSE_US       FINANCE
   │               │                    │                  │                │
①创建客户          │                    │                  │                │
   │               │                    │                  │                │
②创建主订单        │                    │                  │                │
   │               │                    │                  │                │
   │           ③入库→库存管理            │                  │                │
   │               │                    │                  │                │
   │           ④集中装箱                 │                  │                │
   │           (装入集装号)              │                  │                │
   │               │                    │                  │                │
   │           ⑤装箱绑定任务→           │                  │                │
   │           任务开始执行              │                  │                │
   │           (集装号出库               │                  │                │

   │               │                    │                  │                │
   │               │              ⑥推进运输节点             │                │
   │               │              (起运段→到达段)           │                │

### 2.2 各步骤详解

#### ① 创建客户（CRM）
- **操作者**：SALES
- **入口**：海运/空运 → 客户中心 → + 新增客户
- **核心字段**：客户名称、所属行业、公司类型、所在国家、联系人、联系电话、客户来源
- **附属信息**：发货人地址簿（多个）、收货人地址簿（多个）、常用物流设置（偏好运输方式/服务类型/常用线路/付款方式）
- **产物**：客户ID（显示为4位短码如 284Y）
- **客户池**：我的客户 / 公海池（未跟进可回收领取）

#### ② 创建主订单（OMS）
- **操作者**：SALES
- **入口**：海运/空运 → 订单中心 → + 新建订单
- **表单区域**：
  - **基础信息**：客户*（搜索选择）、服务类型*（拼柜海运/拼柜空运）、入仓号、出口方式（买单出口）、线路
  - **发货信息**：姓名*、电话*、详细地址*
  - **收货信息**：姓名*、电话*、国家*、城市*（联动国家）、邮箱、详细地址*
  - **包裹明细**（可多行，支持智能粘贴导入）：物流公司、第三方运单号、品名、货物属性（普货/非普货）、重量Kg、件数、货值USD、备注
- **产物**：主单号（S-/A-{date}{seq}）
- **交付方式**：配送/自提（可选，也可入库后由仓管决定）
- **支付信息**：支付方式（预付/到付）、支付途径（公账/私账）、支付状态（未付/已付）
- **支付收款**：不通过系统收款，由销售或财务线下收款后**上传凭证 → 审批确认 → 更改支付状态**

#### ③ 入库 → 库存管理（WMS-Origin）
- **操作者**：WAREHOUSE_CN
- **入口**：起运国仓储 → 入库记录 → 客户快递入库

**入库操作**：
- 扫描/录入第三方运单号，系统匹配主订单中的包裹
- **每个包裹自动生成一个子单**（主单号-01, -02...）
- 入库后运单进入**库存列表**管理

**入库类型**：
- 客户快递入库：正常流程，快递公司送达仓库
- 调拨到仓入库：从其他站点仓库调拨过来
- 退回入库：退运货物重新入库

**异常处理**：匹配不到订单 → 进入"无订单快递"（可匹配/创单/通知/退回）

**库存列表**：
- 统计：总数、在库、已装箱、总重(kg)、总体积(m³)
- 字段：入库日期（含在库天数）、运单号、业务员、用户、线路
- 操作：编辑、打印、退运

#### ④ 集中装箱（WMS-Origin）
- **操作者**：WAREHOUSE_CN
- **入口**：起运国仓储 → 集中装箱

**操作流程**：
1. 创建线路（选择路线模板），系统生成集装号（KK1, KK2, AK1...）
2. 从库存中选择子单，装入对应集装号
3. 集装号状态：空闲 → 装载中 → 已封箱

> **注意**：海运和空运统一使用"集装号"概念，不再区分集装箱/航空单元。

#### ⑤ 装箱绑定任务 → 任务执行出库（WMS-Origin → TMS）
- **操作者**：WAREHOUSE_CN / OPS_CN

**流程**：
1. 集装号封箱后，绑定到运输任务(JOB)
2. 任务开始执行 = **集装号出库，发往港口（海运）或空运港（空运）**
3. 子单状态从"在库"变为"已装箱"→ 出库后变为"运输中"

**任务(JOB)信息**：
- 任务编号、线路、起运港、目的港、服务类型（普快/特快）
- 筛选条件（普货/非普货/全部/混合）
- 关联的集装号列表（含件数、体积CBM、体积重KGS）
- 供应商信息：供应商名称/电话/地址、航司/船司、提单号、送货公司/司机/车牌

#### ⑥ 推进运输节点（TMS）
- **操作者**：OPS_CN（起运段）→ OPS_US（到达段）
- **入口**：起运国办 / 到达国办 → 任务管理 → 节点更新

**起运国办（OPS_CN 视角）**：
- 任务管理：查看/编辑/删除任务、节点更新、成本录入、详情
- JOB成本：按任务维度录入应付费用（订舱费/拖车费/报关费等）
- 订单费用：按订单维度录入应收费用

**到达国办（OPS_US 视角）**：
- 任务管理：查看任务、节点更新、详情（不可编辑/删除）
- JOB成本 / 订单费用 / DPN成本

**节点更新表单**：集装号*、物流节点*（下拉，选项来自该路线的节点配置）、日期*、异常标记、备注

**任务的状态本质上就是节点推进的状态**，节点链按路线+运输方式自定义配置（系统管理 → 基础设置 → 物流环节）。

**示例：GZ→LOS 海运（7个节点）**：
| 序号 | 节点名称 | 编码 | 阶段标签 | 必填 |
|------|---------|------|---------|------|
| 1 | 起运仓入库 | SEA_INBOUND | 入库 | 是 |
| 2 | 集装 | SEA_PACK | 出库 | 是 |
| 3 | 出口报关 | SEA_EXPORT | 出口报关 | 是 |
| 4 | 离境 | SEA_DEPART | 起运 | 是 |
| 5 | 到港 | SEA_ARRIVE | 到达 | 是 |
| 6 | 进口清关 | SEA_IMPORT | 进口清关 | 是 |
| 7 | 末端派送 | SEA_DELIVERY | 派送 | 是 |

**示例：GZ→LOS 空运（6个节点）**：节点数量和名称可不同于海运

**自定义能力**：
- 每条路线可独立配置自己的节点链（不同路线节点数量和名称可以不同）
- 节点支持排序（上移/下移）、编辑、删除、新增
- 每个节点有：名称、编码、阶段标签（入库/出库/出口报关/起运/到达/进口清关/派送）、是否必填、描述
- 新增路线时需要配置该路线专属的节点链

#### ⑦ 到达国收货（WMS-Dest）
- **操作者**：WAREHOUSE_US
- **入口**：到达国仓储 → 货物入库

**任务到达后的三种处理方式**：
1. **全部入库**：按任务维度扫描入库，所有货物入仓库
2. **直接运输到客户**：部分或全部货物不入库，直接配送给客户
3. **部分送客户 + 部分回仓**：混合处理

**入库子Tab**：
- 任务入库：按任务(JOB)维度入库
- DPN入库：按DPN维度入库（从其他站点调拨来的货物）

**部分入库机制**：
- 一个任务/调拨/DPN/集装号下可能包含多个子运单或集装号，不一定能一次性全部入库
- 因此存在**部分入库**状态：已入库数/总数，逐步核对直到全部完成
- 每次入库操作都有**入库清单**，用于与实物核对（件数、重量、运单号）
- 操作按钮：入库（逐批操作）、清单（查看/打印核对清单）

#### ⑧ 配送 / 自提（WMS-Dest）
- **操作者**：WAREHOUSE_US / DRIVER

**交付方式的确定**：
- 客户下单时**可选择**配送或自提（也可不选）
- 若下单时未选择，入库后由仓管从库存中操作，决定配送还是自提
- 配送和自提**可相互转换**（配送失败可转自提，自提也可转配送）

**配送（送货上门）**：
- 入口：到达国仓储 → 配送列表
- 创建配送时需定义**配送员信息**：姓名、电话
- 统计：配送单总数、执行中、已签收、失败
- 字段：运单编号、DPN、服务类型、发货人、收货人、电话
- 操作：配送完成 / 配送失败 / **转为自提**

**自提（客户到站取货）**：
- 入口：到达国仓储 → 自提列表
- 统计：自提单总数、已通知、已核销
- 字段：自提单号（PUP-）、运单号（DTK-）、收件人、电话、自提站点
- 操作：通知客户 → 核销自提

#### ⑨ DPN / 调拨 — 跨站转运（可选环节）
- **操作者**：WAREHOUSE_CN / WAREHOUSE_US
- **入口**：起运国仓储 → 调拨记录 / 到达国仓储 → DPN管理

**DPN 不是必要环节**，只有当货物需要从当前站点转运到其他站点时才产生。DPN 和调拨本质相同，都是站点间货物转运：
- **起运国**（调拨）：深圳集货区→广州总仓 等
- **到达国**（DPN）：拉各斯站→阿布贾站 等

**流程**：创建转运单 → 绑定运单 → 执行发车 → 目标站确认到达 → 确认入库 → **再进入该站点的配送/自提流程**

**状态**：待绑定 → 待发运 → 运输中 → 已到达 → 已入库 / 已取消

**操作**：详情、绑定运单、执行发车、确认到达、确认入库、打印

**双视角**："我发出的"（建单/绑单/发车）| "发给我的"（确认到达/入库）

#### ⑩ 费用录入 → 审批 → 结算（Finance）

**费用录入有三个入口**：

**A. JOB成本录入**（起运国办/到达国办 → JOB成本）
- 按**任务维度**录入**应付**费用（公司付给供应商的费用）
- 头部信息（只读）：任务号、站点、线路、提单号、服务类型、承运人、件数
- 费用条目（可编辑表格）：
  - 归属层级：JOB公摊 / 集装号公摊
  - 归属对象：JOB编号 / 具体集装号
  - 供应商、费用项目（订舱费/拖车费/报关费等）、单价、数量、币种（CNY/USD/NGN）
- 流程：新增草稿 → 保存草稿 → 提交主管审核
- 统计：任务记录数、草稿数、待审核数、驳回中数、已审核数、应付合计

**B. 订单费用录入**（起运国办/到达国办 → 订单费用）
- 按**订单维度**录入**应收**费用（客户应付给公司的费用）
- **应收直接关联到子运单**（不是主单级别，而是精确到每个子单/包裹）
- 层级：主单 / 子单
- 字段：订单号、主单号、层级、客户名称、站点、线路
- 统计：订单记录数、草稿数、待审核数、驳回中数、已审核数、应收合计、应付合计

**C. 费用录入（统一入口）**（综合协同 → 财务中心 → 费用与成本）
- 汇总所有费用的统一管理视图
- 支持"自动获取费用"从订单/集装号/任务自动补全
- 费用审批：待审批 → 已审批 / 已驳回

**审批流程**（流程管理配置）：
- FEE_APPROVE：费用审批（2节点，已启用）
- 状态链：草稿 → 待审核 → 已审核 / 已驳回（驳回可修改重提）

**审批通过后 → 往来账款**：
- 应付账款：待支付 → 已支付（关联发票号）
- 应收账款：待收款 → 已收款

**最终结算**：
- 任务盈亏看板：应收 - 应付 = 毛利 → 毛利率
- 任务成本总览：按任务维度汇总费用进度
- 所有费用审批完成后 → 任务标记为"已结算"

## 三、辅助业务流程

### 3.1 DPN / 调拨（统一的跨站转运机制）

**DPN 和调拨本质相同**，都是站点间货物转运，共享同一套状态和操作逻辑：
- **起运国场景（调拨）**：深圳集货区→广州总仓、广州总仓→佛山拼货区等
- **到达国场景（DPN）**：拉各斯站→阿布贾站、拉各斯站→卡诺站等

**字段**：转运单号、线路/来源→去向、JOB、订单号/运单号
**统一状态**：待绑定 → 待发运 → 运输中 → 已到达 → 部分入库 → 已入库 / 已取消
**统一操作**：详情、绑定运单、执行（发车）、确认到达、入库（可多次，按清单逐批核对）、打印
> 入库时有清单可核对，支持部分入库，多次操作直到全部完成

### 3.2 退运处理（WMS-Origin → 退运处理）

**场景**：客户要求退回已入库的货物。
**字段**：创建时间、订单信息、业务线、客户、路线/目的地、箱号/集装号、货物信息
**审批**：RETURN_APPROVE（退运审批，2节点）
**流程**：新建退运 → 审批 → 执行退运 → 退回入库

### 3.3 无订单快递（WMS-Origin → 无订单快递）

**场景**：仓库收到快递但无法匹配到任何订单。
**编号**：SEA/AIR-NO-ORDER-{date}-{seq}
**字段**：入库时间（含滞留天数预警）、快递信息、联系人信息、货物信息
**6种操作**：详情 / 编辑 / 匹配（关联已有订单）/ 创单（新建订单）/ 通知（通知客户）/ 退回
**统计**：待处理 / 已匹配 / 已关闭

### 3.4 备用金管理（Finance → 备用金）

**流程**：申请 → 审批（PETTY_CASH_APPROVE, 3节点）→ 发放 → 使用 → 核销
**字段**：申请单号、申请人、申请金额、用途、关联任务、状态

### 3.5 销售提成（Finance → 提成与薪资）

**流程**：选择员工+月份 → 执行计算 → 产出提成结果
**字段**：员工、归属、订单数、运费总额、重量(kg)、提成方案、达标、坏账扣减、提成金额
**彩蛋奖金**：触发总重量 50,000kg，奖金池 ¥3,000，个人最低 3,000kg，最少 2 人

## 四、数据实体关系

### 4.1 实体关系图

```
Client (客户)
  └─1:N─→ MasterOrder (主订单)
              └─1:N─→ SubOrder (子单/包裹，入库时自动生成)
                          └─N:1─→ 集装号 (装箱绑定)
                                    └─N:1─→ Job (运输任务)
                                              ├─1:N─→ TransportNode (运输节点)
                                              ├─1:N─→ DPN/调拨 (跨站转运，统一机制)
                                              │         ├─→ DeliveryTask (配送任务)
                                              │         └─→ PickupTask (自提单)
                                              └─1:N─→ Fee (费用单)
                                                        └─1:1─→ ApprovalFlow (审批流)
                                                                  └─→ AccountPayable/Receivable (往来账款)
```

### 4.2 三条数据流

**正向物流流**：
```
客户 → 主订单(含包裹) → 入库(生成子单) → 库存管理 → 集中装箱(绑集装号)
  → 绑定任务(JOB) → 任务执行(集装号出库→港口) → 节点推进(起运→到达)
  → 到达国收货(入库/直送/部分回仓) → 配送/自提 → 签收完成
                                         │
                                    [可选] DPN跨站调度
                                         │
                                    其他站点入库 → 配送/自提 → 签收完成
```
> DPN 不是必要环节。到达站点收货后可直接配送或等客户自提；
> 只有当货物需要转运到其他站点时才产生 DPN，货物到达其他站点后同样进入配送/自提流程。
```

**资金流**：
```
JOB成本录入(应付) ─→ 主管审核 ─→ 应付账款 ─→ 支付供应商
订单费用录入(应收) ─→ 主管审核 ─→ 应收账款 ─→ 收客户款
汇总: 应收 - 应付 = 任务毛利 → 任务盈亏看板 → 任务结算
```

**信息流**：
```
各环节状态变更 → 工作台角色待办(统计+快速入口)
异常/超时 → 预警中心
月度汇总 → 经营分析看板(营收/成本/毛利/排名)
```

### 4.3 状态机汇总

| 实体 | 状态链 |
|------|--------|
| 主订单 | 待入库 → 部分入库 → 已入库 → 运输中 → 已到达 → 已签收 → 已完成 / 已取消（概括状态，**自动聚合子单状态**：所有子单签收 = 已完成；子单可能分属不同任务，状态差异较大，主单取最概括的状态） |
| 子单 | 待入库 → 在库(IN_STOCK) → 已装箱 → 运输中 → 已到达 → 等待配送/等待自提 → 已签收 |
| 集装号 | 空闲 → 装载中 → 已封箱 → 已绑任务 → 已出库 → **部分入库** → 已入库 |
| 任务(JOB) | 状态 = 当前节点推进位置，按路线自定义节点链逐步推进（如：起运仓入库→集装→出口报关→离境→到港→进口清关→末端派送） |
| DPN/调拨（跨站转运） | 待绑定 → 待发运 → 运输中 → 已到达 → **部分入库** → 已入库 / 已取消 |
| 配送 | 执行中 → 已签收 / 配送失败 / 转为自提 |
| 自提 | 已通知 → 已核销 |
| 费用 | 草稿 → 待审核 → 已审核 / 已驳回 |
| ~~调拨~~ | ~~（已合并到 DPN/调拨）~~ |

## 五、系统管理与基础数据

### 5.1 组织管理（多组织 SaaS 核心）

**站点管理**：
- 仓库类型：起运国仓库 / 到达国仓库 / 中转仓库
- 字段：仓库编码、仓库名称、类型、国家/城市、所属站点、负责人、容量、状态
- **数据隔离**：每个站点只能看到自己站点下的业务数据

**部门管理**：站点内部组织架构配置

**用户 ↔ 站点**：
- 用户可分配到一个或多个站点
- ADMIN/BOSS 为全站点角色，其余角色为分配站点

## 八、跨模块衔接关键点

| 衔接 | 触发条件 | 数据传递 |
|------|---------|---------|
| OMS → WMS-Origin | 入库扫描匹配第三方运单号 | 主订单包裹明细 → 自动生成子单 |
| WMS-Origin → TMS | 集装号封箱绑定JOB | 集装号列表+件数+重量+体积 → 任务 |
| TMS → WMS-Dest | 到达国节点推进到"入库完成" | 任务号→集装号→子单列表 → 到达仓验收 |
| 站点 → 站点 | DPN/调拨（统一的跨站转运） | 子单从A站点调至B站点，起运国和到达国均适用 |
| WMS-Dest → 客户 | 配送/自提 | 配送任务(DTK)/自提单(PUP) → 签收 |
| TMS → Finance | JOB成本录入 | 应付费用 → 审批 → 应付账款 |
| TMS → Finance | 订单费用录入 | 应收费用 → 审批 → 应收账款 |
| Finance → Analytics | 费用审批完成 | 汇总到经营看板(营收/成本/毛利) |

## 九、已明确的业务决策

| 问题 | 决策 |
|------|------|
| 到达国退运 | 暂不考虑，退运只在起运国处理 |
| 客户信用等级 | 仅手动修改，暂不影响业务逻辑 |
| 预警规则 | 暂不定义自动触发规则 |
| 汇率锁定 | 到达国费用录入为外币，**录入时锁定汇率**，不随后续汇率变动 |
| 订单收款 | 不通过系统收款，线下收款后上传凭证审批确认 |
| 主单状态 | 自动聚合子单状态，子单可能分属不同任务，主单取概括状态 |
| 应收粒度 | 应收直接关联到子运单级别 |
| 交付方式 | 下单时可选配送/自提，也可不选由仓管后续决定；配送与自提可互转 |
