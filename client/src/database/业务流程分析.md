# 跨境物流业务流程分析

## 📋 核心业务流程

### 1. 客户管理流程（CRM）
```
公海池 → 销售认领 → 私海客户 → 下单 → 订单管理
```

### 2. 订单处理流程（OMS）
```
订单创建 → 快递预报 → 入库 → 拆单（可选）→ 装箱 → 发货
```

### 3. 仓储管理流程（WMS - 起运国）
```
快递到达 → 扫码入库 → 库存管理 → 装箱（运输单元）→ 出库
```

### 4. 运输管理流程（TMS）
```
创建任务 → 绑定运输单元 → 节点跟踪 → 到达目的国
```

### 5. 到达国仓储流程（WMS - 目的国）
```
到港 → 清关 → 入仓 → 配送 → 签收
```

### 6. 财务管理流程（Finance）
```
费用录入 → 费用审批 → 应收/应付 → 结算
```

---

## 🔗 数据实体关系

### 核心实体
1. **客户（Client）** - CRM模块
2. **主订单（MasterOrder）** - OMS模块
3. **子订单（SubOrder）** - OMS模块
4. **入库记录（InboundRecord）** - WMS模块
5. **运输单元（ShippingUnit）** - WMS/TMS模块
   - 海运集装箱（SeaContainer）
   - 空运货物（AirUnit）
6. **任务（Job）** - TMS模块
7. **费用（Fee）** - Finance模块

---

## 🔍 详细字段映射分析

### 1. Client（客户表）
**主键**: `id`
**关键字段**:
- `shortCode` - 客户简码（唯一）
- `name` - 客户名称
- `poolType` - 客户池类型（公海/私海）
- `salesPerson` - 销售人员
- `contact` - 联系人信息（JSON）
- `logisticsInfo` - 物流信息（JSON）

**关联关系**:
- 1:N → MasterOrder（一个客户可以有多个主订单）

---

### 2. MasterOrder（主订单表）
**主键**: `id`
**外键**: `clientId` → Client.id
**关键字段**:
- `orderNo` - 主运单号（唯一）
- `clientId` - 客户ID
- `totalAmount` - 订单总额
- `status` - 订单状态
- `createdAt` - 创建时间

**关联关系**:
- N:1 → Client（多个订单属于一个客户）
- 1:N → SubOrder（一个主订单可以拆分为多个子订单）

---

### 3. SubOrder（子订单表）
**主键**: `id`
**外键**:
- `masterOrderId` → MasterOrder.id
- `shippingUnitId` → ShippingUnit.id（可选）
**关键字段**:
- `subOrderNo` - 子运单号（唯一）
- `trackingNo` - 快递单号
- `masterOrderId` - 主订单ID
- `shippingUnitId` - 运输单元ID（装箱后）
- `weight` - 重量
- `volume` - 体积
- `pieces` - 件数
- `status` - 状态（CREATED/IN_WAREHOUSE/SHIPPED/ARRIVED/DELIVERED）

**关联关系**:
- N:1 → MasterOrder（多个子订单属于一个主订单）
- 1:N → InboundRecord（一个子订单可以有多次入库记录）
- N:1 → ShippingUnit（多个子订单装入一个运输单元）

---

### 4. InboundRecord（入库记录表）
**主键**: `id`
**外键**: `subOrderId` → SubOrder.id
**关键字段**:
- `subOrderId` - 子订单ID
- `trackingNo` - 快递单号
- `actualWeight` - 实际重量
- `actualVolume` - 实际体积
- `actualPieces` - 实际件数
- `inboundTime` - 入库时间
- `operator` - 操作员
- `warehouseLocation` - 仓库位置

**关联关系**:
- N:1 → SubOrder（多次入库记录对应一个子订单）

---

### 5. ShippingUnit（运输单元 - 抽象）

#### 5.1 SeaContainer（海运集装箱表）
**主键**: `id`
**关键字段**:
- `containerNo` - 集装箱号（唯一）
- `containerType` - 集装箱类型（20GP/40GP/40HQ/45HQ）
- `transportMode` - 运输方式（固定为'SEA'）
- `sealNo` - 封条号
- `maxWeight` - 最大载重
- `maxVolume` - 最大容积
- `currentWeight` - 当前重量
- `currentVolume` - 当前体积
- `loadedPieces` - 已装件数
- `orderIds` - 装载的订单ID数组（JSON）
- `status` - 状态（EMPTY/LOADING/SEALED/SHIPPED/ARRIVED）
- `jobNo` - 任务编号（绑定后）

**关联关系**:
- 1:N → SubOrder（一个集装箱装载多个子订单）
- N:1 → Job（多个集装箱绑定到一个任务）

#### 5.2 AirUnit（空运货物表）
**主键**: `id`
**关键字段**:
- `unitNo` - 单元编号（唯一）
- `unitType` - 单元类型（PALLET/CARTON/LOOSE）
- `transportMode` - 运输方式（固定为'AIR'）
- `mawb` - 主运单号
- `hawb` - 分运单号
- `grossWeight` - 毛重
- `chargeableWeight` - 计费重量
- `volumeWeight` - 体积重
- `pieces` - 件数
- `orderIds` - 装载的订单ID数组（JSON）
- `status` - 状态（RECEIVED/PALLETIZED/SHIPPED/ARRIVED）
- `jobNo` - 任务编号（绑定后）

**关联关系**:
- 1:N → SubOrder（一个空运单元装载多个子订单）
- N:1 → Job（多个空运单元绑定到一个任务）

---

### 6. Job（运输任务表）
**主键**: `jobNo`
**关键字段**:
- `jobNo` - 任务编号（唯一）
- `route` - 路线
- `pol` - 起运港/机场
- `pod` - 目的港/机场
- `carrier` - 承运人
- `vesselVoyage` - 船名/航次（海运）
- `flightNo` - 航班号（空运）
- `transportType` - 运输类型（SEA/AIR）
- `etd` - 预计离港时间
- `eta` - 预计到港时间
- `atd` - 实际离港时间
- `ata` - 实际到港时间
- `status` - 状态
- `currentPhase` - 当前阶段（ORIGIN/IN_TRANSIT/DESTINATION）
- `shippingUnitIds` - 运输单元ID数组（JSON）
- `orderIds` - 订单ID数组（从运输单元汇总，JSON）
- `stats` - 统计信息（JSON）

**关联关系**:
- 1:N → ShippingUnit（一个任务包含多个运输单元）
- 1:N → Fee（一个任务产生多个费用）

**海运与空运区分**:
- 海运任务：使用 `vesselVoyage`（船名/航次），`flightNo` 为 null
- 空运任务：使用 `flightNo`（航班号），`vesselVoyage` 可选

---

### 7. Fee（费用表）
**主键**: `id`
**外键**: `jobNo` → Job.jobNo
**关键字段**:
- `jobNo` - 任务编号
- `feeType` - 费用类型（运费/报关费/仓储费等）
- `amount` - 金额
- `currency` - 币种
- `status` - 状态（PENDING/APPROVED/PAID）
- `approver` - 审批人
- `payer` - 付款人
- `createdAt` - 创建时间

**关联关系**:
- N:1 → Job（多个费用属于一个任务）

---

## ✅ 数据一致性检查结果

### 检查点1: 订单 → 运输单元
- ✅ SubOrder.shippingUnitId 正确引用 ShippingUnit.id
- ✅ ShippingUnit.orderIds 正确包含 SubOrder.id
- ✅ 双向关联一致

### 检查点2: 运输单元 → 任务
- ✅ ShippingUnit.jobNo 正确引用 Job.jobNo
- ✅ Job.shippingUnitIds 正确包含 ShippingUnit.id
- ✅ 双向关联一致

### 检查点3: 任务 → 订单（汇总）
- ✅ Job.orderIds 正确从所有关联的运输单元汇总
- ✅ 统计数据（orders/pieces/weight/volume）准确

### 检查点4: 海运与空运分离
- ✅ SeaContainer 和 AirUnit 类型定义清晰
- ✅ 各自特有字段正确（sealNo vs mawb/hawb）
- ✅ 页面组件正确使用类型守卫
